# Privacy-label answers

> Generated by `node scripts/store.mjs privacy` from `store/privacy-labels.json` (plan W2.24, the privacy report). Don't edit by hand: change the labels file, and its test checks them against the privacy ledger and the published audits.
> נוצר אוטומטית מ-`store/privacy-labels.json`. התשובות נגזרות מדוח הפרטיות; לא עורכים כאן ידנית.

**Basis:** With the default settings (no cloud key, no sync provider, no crash-reporting key in the build) nothing leaves the device: the local-only audit shows 0 non-local requests.

## App Store Connect → App Privacy

1. *Do you or your third-party partners collect data from this app?* → **No, we do not collect data from this app**, for the store build (see the condition below).
2. *Is any data used to track the user?* → **No**
3. Data that a **differently configured build** would collect (declare these only if the store build is made with that setting):

   | Category | Type | Linked to the user | Used for tracking | Only when |
   |---|---|---|---|---|
   | Diagnostics | Crash Data | **No** | **No** | Only in a build made with a crash-reporting key (VITE_SENTRY_DSN), and only until the user opts out (Settings). Personal data is scrubbed before sending (src/lib/telemetry.ts). |

   **The store build is made without `VITE_SENTRY_DSN`**, so the answer to question 1 stays *No*. If a build ever ships with it, declare *Crash Data*: not linked, not used for tracking, *App Functionality*.

*Note:* Everything under optionalFeatures is sent by the user's own choice to the service the user set up (their own key or account); the developer receives none of it.

## Google Play Console → Data safety

1. *Does your app collect or share any of the required user data types?* → **No**
2. *Is all of the user data collected by your app encrypted in transit?* → **Yes**
3. *Do you provide a way for users to request that their data is deleted?* → Nothing is held by the developer; all data is on the device.

   Only in a differently configured build:

   - **App info and performance: Crash logs** (optional for the user): Only in a build made with a crash-reporting key (VITE_SENTRY_DSN), and only until the user opts out.

## Features the user turns on (not collection by the developer)

Both stores ask about data *the developer* collects. These go only where the user sends them, with the user's own key or account, and the developer receives none of it. Mention them in the review notes, not as collected data.

| Feature | Sends | Turned on by |
|---|---|---|
| Cloud AI (OpenAI, Anthropic, Google Gemini, Mistral) | The text you send to the AI | Your own API key and the cloud or local-first AI policy; refused under local-only |
| Cloud grammar check (LanguageTool) | The text being checked | A policy other than local-only; refused under local-only |
| Research service | Your search query | Running a research command with a research service configured; refused under local-only |
| Canvas (tldraw) licence check | The page address | Opening a canvas in a production build; refused under local-only |
| Model and dictionary downloads (Hugging Face, GitHub) | Nothing of yours (a download) | Choosing a local model or a dictionary |
| Canvas fonts, icons and translations | Nothing of yours (static files) | Opening a canvas |
| Other requests in audit mode | Whatever that request carries; listed so an audit can compare | Audit mode only (lumen.privacy.audit) |
| Encrypted sync (WebDAV, S3, Dropbox, Google Drive) | Ciphertext only, to the storage you chose | Connecting a sync provider |
| Live collaboration | End-to-end encrypted edits, to your collaborators (and a collab server, if configured) | Starting or joining a session |
