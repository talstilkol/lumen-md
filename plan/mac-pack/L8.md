## The `expect` format

Each entry's `expect` is machine-checkable, so one aggregator can read every lane's pack:

- `exit`: the command's exit code.
- `json` + `checks`: a JSON file the command writes; each check is `{path, op, value}`. `path` is a list of keys (a key may contain dots, e.g. `"wer.fleurs"`); an object segment such as `{"id": "fim"}` picks the array element whose fields match. `op` is one of `==`, `!=`, `>=`, `<=`, `>`, `<`. `{"op": "count", "where": {...}, "gte": N}` counts the array elements at `path` whose fields match.
- `file` + `regex` (+ `group1Gte`): a text log the command tees; the regex must match, and its first group as a number must be ≥ the value.
- `batch`: entries with the same batch share one run of the same command (run it once).
- vitest entries write `--reporter=json` (`success`, `numFailedTests`, `numPendingTests` = skipped, `numTotalTests`); Playwright entries write the JSON reporter (`stats.expected`, `unexpected`, `flaky`, `skipped`). A skipped test fails the entry: a skip is not a pass.

Every output goes to `reports/mac-pack/L8/` (git-ignored). `needs` names what must exist first: another entry's id, a branch from this lane, a tool, a model, a secret or the owner.
