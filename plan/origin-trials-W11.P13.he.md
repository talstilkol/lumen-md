# ניסויי Origin Trial ל-Chrome 148 (W11.P13): מה צריך

כפתור ההתקנה של Lumen (src/pwa/install.ts) משתמש בשתי תכונות של Chrome
שעדיין בניסוי origin trial. הראשונה היא הרכיב `<install>`
(`HTMLInstallElement`), והשנייה היא `navigator.install()` (ה-Web Install
API). שתיהן מזוהות בזמן ריצה. בלעדיהן האפליקציה עוברת ל-`beforeinstallprompt`,
ואחריו למדריך לפי דפדפן. הקוד גמור (#808). חסרים האסימונים ובדיקה אחת ב-Chrome 148 אמיתי.

## 1. רישום (הבעלים, פעם אחת לכל ניסוי)

- ב-developer.chrome.com/origintrials מתחברים ורושמים את שני הניסויים
  למקור `https://lumen-md.vercel.app`: הניסוי של רכיב ההתקנה והניסוי של
  ה-Web Install API. את השמות המדויקים, תאריכי הסיום וגרסאות Chrome לוקחים
  מדף הניסוי עצמו. התוכנית לא מעתיקה אותם כי הם משתנים.
- אסימון אחד לכל מקור. גרסאות preview (‏`*.vercel.app`) לא מקבלות אסימון:
  `vercel.app` הוא סיומת ציבורית, ולכן "התאמה לכל תתי-הדומיינים" לא מכסה אותן.
  ב-preview נשארים המסלולים החלופיים, שה-e2e בודק.
- רק אסימונים של צד ראשון (לא "third-party"): Lumen מגיש את הדפים של עצמו.

## 2. מסירת האסימונים

- אסימונים הם ציבוריים: הם נשלחים לדפדפן של כל מבקר. הם לא סודות, ולא נכנסים לאחסון הסודות.
- הדרך המועדפת: כותרת תשובה `Origin-Trial: <token>` אחת לכל ניסוי, על מסמך
  ה-HTML של האפליקציה. מוסיפים אותן לכותרות המסמך ב-`security/policy.json`
  ומרנדרים עם `npm run headers`. זו כותרת ליד ה-CSP, וה-CSP עצמו לא משתנה.
  אין צורך לבנות מחדש את החבילה, ואין משתנה `VITE_*` (אסור להוסיף כזה).
- דרך חלופית: `<meta http-equiv="origin-trial" content="…">` ב-`index.html`.
  היא פחות טובה, כי החלפת אסימון דורשת בנייה.
- בודקים כל אסימון לפני שהוא עולה, ושוב כל חודש:
  `node scripts/pwa/origin-trial-token.mjs --origin https://lumen-md.vercel.app <token>…`.
  הבדיקה יוצאת עם קוד 1 כשהמקור שגוי, כשהאסימון של צד שלישי, כשפג תוקפו,
  או כשתוקפו פג בתוך 30 יום.

## 3. אימות (הרצת ה-Mac)

- `FC2-W11.P13-origin-trials`, ואחריו `L8-W11.P13-chrome`: ‏`e2e/pwa-install.spec.ts`
  ב-Google Chrome 148 ומעלה מול production. המקרה שאינו מזויף רושם איזה מסלול
  Chrome מציע (`element` או `api`).
- מקומית, בלי אסימון: מפעילים את שתי התכונות ב-`chrome://flags` (שמות הדגלים
  מופיעים בדף כל ניסוי) ומריצים את אותו spec.

## 4. כשניסוי מסתיים

- Chrome מפסיק לחשוף את התכונה בתאריך הסיום. install.ts עובר לחלופה בעצמו, ושום דבר לא נשבר.
- מסירים את הכותרת שפג תוקפה (בדיקת האסימון נכשלת 30 יום לפני הסיום). אם
  התכונה יוצאת רשמית, מוחקים את הכותרת. אם הניסוי מוארך, נרשמים שוב לאסימון חדש.

## פעולות הבעלים

1. לרשום את שני הניסויים ל-`https://lumen-md.vercel.app`.
2. לשים את שני האסימונים בכותרות המסמך (`security/policy.json`,
   `npm run headers`) ולפרוס.
3. להריץ את בדיקת האסימונים, ואחריה את `L8-W11.P13-chrome` ב-Chrome 148 ומעלה.
