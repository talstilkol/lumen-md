ל-Lumen יש שני שרתים קטנים. שניהם מחזיקים רק מידע מוצפן.

- **שרת השיתוף החי** (`edge-workers/collab/`) מעביר חדרים של
  [שיתוף חי](/he/collab/public-server/).
- **ממסר הסנכרון המוצפן** (`edge-workers/vault-relay/`) שומר את הקבצים
  המוצפנים של [הסנכרון המוצפן](/he/sync/e2ee/) למכשירים שאין להם תיקיית
  סנכרון ואין להם WebDAV. הקוד שלו הוא הקוד של הממסר ב-Node,
  `sync-server/vault-relay.js`.

שניהם רצים על **Cloudflare Workers עם Durable Objects**, בתוכנית החינמית.

## פריסה של שניהם בפקודה אחת

בעל חשבון Cloudflare מריץ:

```sh
npm run share:deploy
```

אם צריך, הפקודה מתחברת קודם ל-Cloudflare (`wrangler login` פותח את
הדפדפן). אחר כך היא פורסת את `lumen-collab` ואת `lumen-vault-relay` ובודקת
את ה-`/healthz` של כל אחד. בסוף היא מדפיסה את שלושת משתני הבנייה של
האפליקציה: `VITE_YJS_WEBSOCKET_URL`, ‏`VITE_WEBRTC_SIGNALING_URL`
ו-`VITE_SYNC_RELAY_URL`.

- `npm run share:deploy -- --bundle-only` בונה את שני ה-Workers ולא פורס
  כלום.
- `npm run share:deploy -- --dry-run` מדפיס כל פקודה ולא מריץ אף אחת.

## ישיבת הבעלים: פריסה ובדיקה

```sh
npm run owner:share
```

הפקודה מריצה את הפריסה שלמעלה ואחריה ארבע בדיקות. אם בדיקה אחת נכשלת,
היא עוצרת עם שגיאה.

1. **השהיה מהמקום שבו אתם נמצאים.** שני לקוחות עורכים חדר אחד דרך שרת
   השיתוף החי. לקוח שלישי כותב וקורא בחזרה דרך הממסר. ה-p95 צריך להיות
   מתחת ל-**150ms**. כדאי להריץ את זה מישראל, כי ההשהיה שקובעת היא שלכם.
2. **המגבלות של הממסר על השרתים האמיתיים.** נפרס עותק זמני של הממסר עם
   מגבלות זעירות (64KiB בסך הכול, שני מרחבים חדשים ביום לכל כתובת). הבדיקה
   מוודאת שמרחב שלישי מהכתובת שלכם מקבל 429, ושכתיבה מעבר ל-64KiB מקבלת
   507. אחר כך העותק נמחק. ‏Wrangler שואל לפני המחיקה, ועונים `y`.
3. **אין טקסט של פתקים ביומנים.** בזמן ששלב 1 כותב פתק בדיקה ידוע,
   `wrangler tail` מקליט את שני השרתים. ‏`share:scan` מחפש את הפתק
   בהקלטות כטקסט רגיל, כ-UTF-16, כ-hex וכ-base64, וצריך למצוא 0 התאמות.
4. **קבלה** נשמרת ב-`~/.lumen-owner/share-receipt-<time>.json`.

ולסיום, ביד: פותחים קישור שיתוף אחד בשני דפדפנים בשתי רשתות, למשל מחשב
נייד ב-Wi-Fi וטלפון ברשת הסלולרית, ועורכים יחד.

לניטור זמינות מוסיפים את שתי כתובות ה-`/healthz` לשירות ניטור חינמי כמו
UptimeRobot, ומפעילים בו את דף הסטטוס הציבורי.

## המגבלות של הממסר ב-Workers

| הגדרה | ב-Workers | למה |
|---|---|---|
| `VAULT_RELAY_MAX_OBJECT` | ‏2MiB | בתוכנית החינמית בקשה מקבלת 10ms של CPU. שמירת קובץ קוראת אותו, מחשבת לו hash וכותבת אותו: במדידה שלנו זה לקח בערך 6ms ל-2MiB ו-12ms ל-4MiB. לקבצים של עד 25MiB אפשר להריץ ממסר משלכם (`sync-server`, ‏`VAULT_RELAY=1`). |
| `VAULT_RELAY_MAX_TOTAL` | ‏768MiB | התקרה לכל המרחבים יחד. בתוכנית החינמית יש 5GB אחסון לכל חשבון, ושרת השיתוף החי יכול להשתמש בעד 4GB מהם. |
| `VAULT_RELAY_NEW_SPACES_PER_DAY` | 5 | מרחבים חדשים לכל כתובת (כתובת IPv4, או ‎/64 של IPv6) ביום UTC. |
| `VAULT_RELAY_ADDRESS_BYTES_PER_DAY` | ‏128MiB | כמה בתים כתובת אחת יכולה לכתוב ביום UTC. |
| `VAULT_RELAY_POW_BITS` | 18 | מרחב חדש עולה לאפליקציה הוכחת עבודה קצרה. |

הספירות היומיות נשמרות באחסון של ה-Durable Object, כך שהן נשארות בתוקף
גם אחרי ש-Cloudflare פורק אובייקט שאף אחד לא משתמש בו. הן נשמרות תחת hash
עם מפתח שמתחלף כל יום, ואף פעם לא ככתובות. כשמתחיל יום חדש, הספירות
והמפתח של היום הקודם נמחקים.

## בדיקה מהמחשב שלכם

```sh
node scripts/share-latency.mjs --collab wss://<collab>/ --relay https://<relay> --big
node scripts/share-scan.mjs --text "שורה מהפתק שלכם" <תיקייה או קובץ יומן>
```

`share-scan` מחפש בקבצים ובתיקיות, כולל מסדי נתונים של SQLite. אם הוא
מוצא התאמה, הוא מציג כל אחת ויוצא עם קוד 1.
