השער (תוכנית 8.3) בודק שבנייה נטענת מהר מספיק לפני שהיא יוצאת. הוא רץ
במחשב שלכם או מול פריסת preview, בלי GitHub Actions.

```bash
npm run build && npm run perf:gate            # מגיש את dist/ עם vite preview
npm run perf:gate -- --url https://<preview>.vercel.app
```

## מה נמדד

‏Lighthouse CI לא נמצא ב־lockfile, ולכן השער מודד את אותם מספרים בעצמו, עם
Playwright ורשומות הביצועים של Chromium עצמו:

- ‏**FCP**: הציור התוכני הראשון.
- ‏**LCP**: הציור התוכני הגדול ביותר.
- ‏**CLS**: תזוזות פריסה שלא נגרמו מקלט.
- ‏**TBT**: לכל משימה ארוכה אחרי FCP, הזמן שמעבר ל־50 מ״ש, כמו ש־Lighthouse
  סופר.
- ‏**TTI**: סוף המשימה הארוכה האחרונה לפני חלון שקט.
- גם הזמן עד שהעורך מקבל קלט מדווח.

כל טעינה קרה: הקשר דפדפן חדש, בלי מטמון, בלי אחסון ובלי service worker. יש
5 טעינות לכל פרופיל, והשער מדווח על **הריצה החציונית**: הטעינה האחת
הקרובה ביותר לחציון של FCP ו־TTI. זה תואם ל־`median-run` של Lighthouse,
ולא לברירת המחדל האופטימית שלו.

| פרופיל | הדמיה |
|---|---|
| ‏desktop | ‏1350 × 940, בלי האטה |
| ‏mobile | ‏Pixel 7, מעבד איטי פי 4, השהיה של 150 מ״ש, הורדה ב־1.6 Mbps |

## ספים

הספים נמצאים ב־`perf-gate.config.json`:

- ‏**`error`** מכשיל את השער (קוד יציאה 1).
- ‏**`warn`** רק מדווח.
- ‏**`target`** הוא היעד של התוכנית, ומוצג ליד התוצאה עד שהסביבה מגיעה
  אליו.

בפרופיל desktop, ספי השגיאה הם הרמה שנקבעה בהחלטה ‎15.16 (20)/(21)‎:
FCP של 1200 מ״ש ו־LCP של 3500 מ״ש, עם יעדים של 1000 ו־2500 מ״ש. תוכניות
8.1 ו־8.2 מהדקות אותם. פרופיל mobile רק מזהיר עד שימדדו אותו בסביבה.

## אפשרויות

| אפשרות | משמעות |
|---|---|
| ‏`--url <url>` | מדידה של שרת או פריסה שכבר רצים, במקום `vite preview` |
| ‏`--profiles desktop` | רק הפרופילים האלה |
| ‏`--runs 3` | טעינות לכל פרופיל (ברירת המחדל: 5) |
| ‏`--out gate.md` | סיכום Markdown, לתגובה ב־PR |
| ‏`--json gate.json` | כל הריצות וכל המדדים |

‏`npm run lighthouse` ‏(LHCI) עדיין עובד כשמתקינים אותו עם `npx`. השער לא
תלוי בו.
