## חמש דקות מכלום ועד תוסף שרץ

```bash
npx create-lumen-plugin my-plugin
cd my-plugin
npm run dev        # http://127.0.0.1:5199, עוקב אחרי התיקייה
```

1. בלומן פותחים את **גלריית התוספים**, ובתחתית **מצב מפתחים**. משאירים
   את `http://127.0.0.1:5199` ולוחצים **התחברות**.
2. `⌘K` ← **My plugin**: החלונית הצדדית מציגה את מספר המילים בפתק.
3. משנים את `main.js` ושומרים. לומן טוען את התוסף מחדש לבד, בדרך כלל
   בהרבה פחות משנייה. החלונית מראה כמה זמן לקחה הטעינה האחרונה.

אין מה להתקין: שרת הפיתוח וערכת הבדיקות צריכים רק Node (גרסה 20 ומעלה).

## מה יש בתיקייה

| קובץ | מה הוא |
|---|---|
| `lumen-plugin.json` | המניפסט: מזהה, שם, גרסה, והיכולות שהתוסף מבקש, כל אחת עם הסיבה שהמשתמש רואה. |
| `main.js` | התוסף. הוא רץ ב[ארגז החול](/he/plugins/sandbox/): רק ה־API של `lumen`, בלי DOM, ובלי רשת אלא אם ביקש. |
| `test/main.test.mjs` | בדיקות, מריצים עם `npm test`. |
| `tools/dev-server.mjs` | שרת הפיתוח שמאחורי `npm run dev`. |
| `tools/testkit.mjs` | ערכת הבדיקות. |

## מצב מפתחים

במצב מפתחים התוסף נטען משרת הפיתוח ולא מהגלריה:

- הוא מתחבר רק למחשב הזה (`localhost`,‏ `127.0.0.1`,‏ `[::1]`).
- השאירו את שרת הפיתוח בפורט 5199: מדיניות האבטחה של האפליקציה (CSP)
  מתירה במחשב הזה את הפורט הזה בלבד.
- התוסף מקבל את היכולות שהמניפסט מבקש, בלי מסך ההרשאות: זה הקוד שלכם.
- כל גרסה עדיין עוברת את [סריקת הבטיחות](/he/plugins/permissions/),
  והחלונית מציגה את ההערות שלה. כאן הסריקה לא חוסמת את התוסף שלכם, אבל
  הגלריה לא תציג גרסה שנכשלה בה.
- בכל שמירה שרת הפיתוח שולח אירוע `change`, ולומן טוען שוב את המניפסט
  ואת `main.js`. שינויים שמגיעים בזמן טעינה מצטרפים לטעינה אחת נוספת.

## חלונית המפתחים

כל עוד התוסף רץ, החלונית מציגה:

- **טעינות מחדש**: כמה היו, כמה זמן לקחה האחרונה (מהשמירה ועד שהתוסף
  רץ שוב), וכמה זמן לקחה ההפעלה.
- **מעבד וזיכרון**: הזמן שהקוד של התוסף רץ, כמה הרצות היו, מה הייתה
  הארוכה ביותר, והזיכרון של ארגז החול.
- **הרשאות: מה התבקש ומה נוצל**: כל יכולת במניפסט, כמה פעמים השתמשו בה
  וכמה פעמים נדחתה. יכולת שלא נוצלה מסומנת: בקשו רק את מה שאתם צריכים,
  כי המשתמשים רואים את הרשימה לפני ההתקנה.
- **הקריאות האחרונות**: הקריאות האחרונות של התוסף ללומן, כמה זמן לקחה
  כל אחת והאם נדחתה.

## בדיקות ב־Node

```js
import { test } from "node:test";
import assert from "node:assert/strict";
import { loadPlugin } from "../tools/testkit.mjs";

test("shows the count", async () => {
  const p = await loadPlugin({ dir: ".", document: { text: "שלום עולם" } });
  await p.run("show");                       // פקודה שהתוסף רשם
  assert.equal(p.panel.tree.type, "box");    // החלונית שהוא הציג
});

test("needs document:read", async () => {
  const p = await loadPlugin({ dir: ".", grants: ["commands", "panel"] });
  await assert.rejects(p.run("show"), { name: "PluginDenied" });
});
```

`loadPlugin` מריץ את `main.js` בהקשר `vm` חדש של Node, מול חיקוי של
ה־API של `lumen`. הוא שומר על הכללים של ארגז החול:

- טבלת השיטות זהה (בדיקה בלומן שומרת על כך).
- קריאה בלי היכולת שלה נדחית עם `PluginDenied`.
- הארגומנטים חייבים להיות JSON.

המצב המדומה כולל את `document` (‏`text`,‏ `fileName`,‏ `selection`), את
`vault` (‏`{"folder/note.md": text}`), את `settings`, את `storage`, ואת
`fetch` לקריאות רשת שאושרו.

מקבלים בחזרה את מה שהתוסף עשה: `commands`,‏ `panel`,‏ `rendered`,‏
`document`,‏ `vault`,‏ `storage`,‏ `notifications`,‏ `clipboard`,‏ `logs`,‏
`calls` ו־`denied`.

מפעילים אותו עם:

- `run(id, payload)`
- `emit(name, payload)` (למשל `"ui:panel"`)
- `render(lang, source)` לתוסף שמציג בלוק קוד
- `select(from, to)`

‏Node הוא לא QuickJS, ולכן בדקו גם בלומן לפני פרסום. שני הבדלים שכדאי
לזכור: ל־QuickJS אין `Intl`, וארגז החול מגביל זמן מעבד וזיכרון.

## דוגמאות

שמונה הדוגמאות של הגלריה נמצאות ב־`public/plugins/examples/`:

| דוגמה | מה היא מראה |
|---|---|
| ‏Word stats | חלונית, הגדרות, ספירה בעברית ובאנגלית |
| ‏Callout cards | תצוגה של בלוק קוד, אחסון |
| ‏Quote of the day | גישה לרשת, לכתובת אחת בלבד |
| ‏Table of contents | קריאה מהפתק וכתיבה אליו |
| ‏Hebrew date | תצוגה ופקודה, לוח שנה שמחושב בלי `Intl` |
| ‏Tasks overview | קריאה של כל הכספת (`vault:read`), חלונית עם קישורים לפתקים |
| ‏Bidi cleaner | הבחירה או הפתק כולו, התראות |
| ‏Text format | הסבה של תוסף Obsidian ‏(MIT), כמה פקודות |

## פרסום

מעלים את `version` ב־`lumen-plugin.json` ופותחים pull request שמוסיף את
התיקייה תחת `public/plugins/examples/` ושורה ב־`index.json` שלה. קודם
מריצים את `node scripts/scan-plugins.mjs`: כל גרסה נסרקת, וגרסה שנכשלת
לא מוצגת.
