החלק **תוספים בארגז חול** בגלריית התוספים מציג תוספים מרישום סטטי שמגיע עם
Lumen. אין שרת תוספים: הרישום הוא תיקייה של קבצים, וכל גרסה בו עוברת את סריקת
הבטיחות לפני שהיא מוצגת.

## עשרת התוספים

התוספים בנויים לפי סוגי תוספי Obsidian שמורידים הכי הרבה: תבניות, לוחות
משימות, לוחות שנה, טבלאות, סידור טקסט, תגיות, חזרה מרווחת, ארגון מחדש של
פתקים, תאריכים ומיון. כל אחד מהם נכתב לארגז החול של Lumen. אף אחד מהם לא
משתמש ברשת, ולכן כולם עובדים גם במדיניות AI **מקומית בלבד**.

| תוסף | מה הוא עושה | הרשאות |
| --- | --- | --- |

כדי להתקין תוסף: **גלריית התוספים ← תוספים בארגז חול ← התקנה…**. מסך ההרשאות
מפרט כל מה שהתוסף מבקש, ולמה. אחרי ההתקנה מופיע בכרטיס הכפתור **הסרה**: הוא
עוצר את התוסף ומוחק את ההגדרות והנתונים ששמר.

התוויות של התוספים כתובות באנגלית ובעברית, כי ממשק התוספים לא מוסר לתוסף באיזו
שפה האפליקציה פועלת.

## איך הרישום נבנה

```
public/plugins/examples/
  index.json          ← נבנה: כל תוסף, הגרסאות שלו, ו-SHA-256 של הקוד ושל המניפסט של כל גרסה
  index.json.sig      ← חתימת Ed25519 של הבעלים על index.json (נכתבת ב-‎--sign)
  scan.json           ← נבנה: סריקת הבטיחות של כל גרסה
  kanban/             ← תיקייה לכל גרסה
    lumen-plugin.json
    main.js
```

```sh
node scripts/build-plugin-registry.mjs           # בונה מחדש את index.json ואת scan.json
node scripts/build-plugin-registry.mjs --check   # נכשל אם אחד מהם לא מעודכן, גרסה נכשלה בסריקה, או ש-index.json.sig כבר לא מתאים
```

הבנייה עושה את הדברים האלה:

- בודקת כל מניפסט;
- דוחה קבצים מיותרים בתיקיית תוסף (מותרים רק המניפסט, הקבצים שהוא מפנה אליהם, `LICENSE` ו-`README`);
- דוחה מזהה וגרסה שמופיעים פעמיים;
- כותבת את `index.json`;
- סורקת כל גרסה (`scripts/scan-plugins.mjs`).

גרסה חדשה נכנסת לתיקייה משלה, למשל `kanban@1.1.0`.

בזמן ההתקנה האפליקציה סורקת שוב את הקוד שהורד. היא דוחה אותו אם ה-SHA-256 שלו
שונה מהטביעה שבסריקת הרישום.

בודקים שהרישום מעודכן (הדוגמה הזאת רצה בבדיקת התיעוד):

```sh run
node scripts/build-plugin-registry.mjs --check
```

## בגלריה

- **התקנה** מריצה תוסף רק מחבילה שעברה את המסלול החתום שלמטה. תוסף ממאגר
  שאין לו עדיין חבילה חתומה מוצג כ**לא זמין עדיין**, ושום דבר לא מורד או רץ.
- **מאומת על ידי Lumen** מופיע רק כשהחתימה של המאגר אומתה מול מפתח נעוץ.
  כל תוסף אחר מסומן **לא מאומת**: חתימה חסרה או לא מוכרת לעולם לא נחשבת
  מאומתת.

## הרישום החתום

הבעלים חותם על הבתים המדויקים של `index.json` במפתח Ed25519 שנשאר במחשב של
הבעלים. מכיוון ש-`index.json` מפרט את ה-SHA-256 של הקוד ושל המניפסט של כל
גרסה, החתימה האחת הזאת מכסה כל קובץ שאפשר להתקין.

```sh
node scripts/build-plugin-registry.mjs --keygen ~/keys      # פעם אחת: מפתח חדש; מדפיס את הערך של VITE_PLUGIN_TRUSTED_KEYS
LUMEN_PLUGIN_SIGNING_KEY=~/keys/lumen-plugin-registry.pem node scripts/build-plugin-registry.mjs --sign
```

מגדירים את `VITE_PLUGIN_TRUSTED_KEYS` שהודפס בסביבת הבנייה. האפליקציה סומכת רק
על המפתח הזה, או על מפתח שסמכתם עליו בעצמכם בהגדרות. המפתח הציבורי שכתוב
ב-`index.json.sig` לא נחשב מהימן בפני עצמו.

כשבתיקייה יש `index.json.sig`, **התקנה** עוברת במסלול החתום
(`src/plugins/install.ts`), וכל שלב יכול לדחות את ההתקנה:

1. מורידים את `index.json` ואת `index.json.sig`. ההורדות רשומות ביומן הפרטיות.
2. החתימה על `index.json` חייבת להיות תקפה מול מפתח מהימן. בית אחד ששונה
   במקום כלשהו ב-`index.json` נכשל כאן.
3. מורידים את המניפסט ואת הקוד, וה-SHA-256 של כל אחד מהם חייב להתאים
   ל-`index.json` החתום.
4. הקוד נסרק, ואז רץ בארגז החול של QuickJS עם ההרשאות שהמניפסט מצהיר עליהן,
   כפי שהן מופיעות במסך ההרשאות.

**הסרה** עוצרת את ארגז החול, מוחקת את מה שהתוסף שמר ומוחקת את רשומת ההתקנה
ואת ההרשאות שלו.

רישום מאתר אחר מותקן רק במסלול הזה, ורישום לא חתום נדחה. רק התיקייה שמגיעה עם
האפליקציה (`/plugins/examples`), שמוגשת מהמקור של האפליקציה עצמה, חוזרת לבדיקת
ה-SHA-256 מול הסריקה כשאין בה `index.json.sig`.

## ערכות נושא שנבדקו ב-RTL (W12.S6)

כל ערכת נושא בגלריה (`public/themes/examples/`) עוברת ביקורת כמו גרסת תוסף שיש בה רק גיליון סגנונות (הביקורת שבדף [אבטחה](/he/security/): רישיון, מקור ציבורי, בלי CSS מרוחק), ואחר כך בדיקה לשימוש מימין לשמאל. `node scripts/themes/rtl-check.mjs` כותב את כרטיס הניקוד שלה ל-`public/themes/examples/scorecards/<id>@<version>.json`; ‏`--check` נכשל כשכרטיס לא עדכני, ו-`--css <file>` בודק גיליון אחד.

- **CSS פיזי.** `margin-left`, `padding-right`, `left:`/`right:`, גבול או פינה בצד אחד, ו-`float`, `clear` ו-`text-align` עם `left`/`right` שוברים פריסה בעברית. כל אחד מדווח עם המאפיין הלוגי שצריך במקומו (`margin-inline-start`, `text-align: start` וכו׳). כלל שמוגבל לכיוון אחד (`[dir="rtl"] …`, `:dir(ltr)`) מותר.
- **ניגודיות** (WCAG 2.2, ‏1.4.3): צבעי הטקסט של הערכה מול הרקעים שלה, 4.5:1, במצב בהיר ובמצב כהה. הצבעים של האפליקציה משלימים את מה שהערכה לא קובעת.
- **מסכים.** שמונה מסכים (עורך, תצוגה, טבלה, רשימות, callouts, קוד בתוך עברית, Bases, הגדרות) מצולמים ב-RTL וב-LTR בהרצה בדפדפן, ומשולבים עם `--screens <results.json>`.

בדיקת RTL שנכשלת היא אזהרה בכרטיס, לא הסרה מהרשימה: כל ממצא מוריד מהניקוד כמו כל אזהרת ביקורת (10 נקודות). התג **נבדק ב-RTL** ניתן רק כששלושתן עוברות, ולכן הוא מחכה להרצה בדפדפן. אין דירוגים של משתמשים: דירוגים צריכים חשבונות ופיקוח, וכרטיס הניקוד והתג עושים את העבודה הזאת.

## אתר רישום משלו

אפשר לפרסם את אותו רישום גם כאתר סטטי משלו ב-Cloudflare Pages, המארח השני.
כך מפתח מחוץ לפרויקט יכול להוסיף תוסף לרישום בבקשת משיכה, בלי לחכות לגרסה
חדשה של האפליקציה.

```sh
npm run registry:site                 # בונה את dist-registry/ (קודם בודק ש-index.json ו-scan.json מעודכנים)
npm run registry:verify -- dist-registry
npx wrangler pages deploy dist-registry --project-name lumen-md-plugins --branch main
npm run registry:verify -- https://lumen-md-plugins.pages.dev
```

באתר יש:

- `v1/index.json`: כל תוסף וכל גרסה שעברה את הסריקה, עם ההרשאות, הציון
  והממצאים של הסריקה, וה-SHA-256 והגודל של כל קובץ. גרסה שנכשלה בסריקה לא
  נכללת.
- `v1/plugins/<id>/<version>/`: הקבצים עצמם. הם מוגשים כטקסט ולא משתנים
  לעולם, ולכן אפשר לשמור אותם במטמון לתמיד.
- `SHA256SUMS`, בפורמט ש-`sha256sum -c` קורא.
- `index.html`: הרשימה, בעברית ובאנגלית, בלי סקריפטים.
- `_headers`: `nosniff`, ‏CORS לקריאה בלבד, ו-CSP שלא מתיר להריץ דבר.

`registry:verify` מחשב מחדש כל טביעה **וסורק שוב כל גרסה** במחשב שלכם.
מארח ששינה קובץ, או שמציג גרסה שהסריקה הייתה דוחה, נכשל בבדיקה. האתר נכנס
בתוכנית החינמית בשפע: 40 קבצים מתוך 20,000 המותרים, ו-4 כללי כותרות מתוך 100.

האפליקציה עדיין קוראת את הרישום שמגיע איתה (`/plugins/examples`). קריאה של
האתר הזה מתוך האפליקציה היא צעד נפרד, כי ה-CSP של האפליקציה יצטרך את הכתובת שלו.

## עוד לא

- הרישום שמגיע עם האפליקציה **עוד לא חתום**: כדי לחתום עליו צריך את המפתח של
  הבעלים (‎`--keygen` ואז ‎`--sign`, למעלה), ולכן בכרטיסים שלו עדיין מופיעה
  ההערה „לא חתום”. ראו גם [מפתחות לחתימת תוספים](/he/plugins/signing/).
- אתר הרישום (`npm run registry:site`) עוד לא מפרסם את `index.json.sig`,
  והאפליקציה עוד לא קוראת את האתר הזה.
