גבולות הגודל והמהירות של Lumen זזים רק לכיוון אחד: למטה (תוכנית W6.26).
תקציב שלא יורד אחרי חיסכון מזמין את הגדילה הבאה.

## איפה הגבולות

| קובץ | מה הוא מגביל | מי אוכף |
|---|---|---|
| `scripts/bundle-budgets.json` | כל סוג chunk (KB דחוס, לכל קובץ) ואת סך ה־startup | `npm run budget` |
| `perf-gate.config.json` | ‏FCP ו־LCP של כל פרופיל, ושאר המדדים | `npm run perf:gate` |
| `lighthouserc.json` | הציונים והמדדים של Lighthouse | `npm run lighthouse` |

הכלל הראשון ב־`bundle-budgets.json` שהתבנית שלו מתאימה לשם הקובץ קובע את
התקציב של הקובץ, ולכן תבניות צרות באות קודם.

## אחרי כל רכבת: ה־ratchet

בניית ה־Vercel של הרכבת מריצה את שער התקציב, והוא כותב את הקבלה
`reports/bundle-sizes.json` ומדפיס אותה כשורה אחת `bundle-sizes: {…}`
ביומן הבנייה. נותנים ל־ratchet את אחת מהן:

```bash
npm run budget:ratchet -- --sizes reports/bundle-sizes.json --train train-3 --sha <head>
npm run budget:ratchet -- --sizes-log vercel-build.log --perf perf-gate.json --first-party startup.log --write
```

- כל תקציב נהיה הקובץ הגדול ביותר שנמדד בסוג שלו ועוד 2% (לפחות 1 KB),
  מעוגל למעלה ל־KB שלם, ורק אם זה נמוך מהתקציב של היום. סך ה־startup
  עובד באותה דרך.
- עם `--perf` ‏(ה־JSON של `npm run perf:gate -- --json`), ספי ה־FCP וה־LCP
  ‏(`error` ו־`warn`) נהיים הריצה החציונית ועוד 2% (לפחות 50 ms), אם זה
  נמוך יותר. היעדים לא משתנים.
- ‏`--first-party` מקבל את היומן של מדידת ה־startup הלא־מקוונת
  (`startup first-party: … KB gz`) ורושם אותו בהיסטוריה, כי בניית Vite לא
  מבחינה בין הקוד שלנו לקוד של חבילות.
- בלי `--write` הוא רק מדפיס מה היה יורד. עם `--write` הוא מעדכן את
  הקבצים ומוסיף שורה ל־`history` ב־`bundle-budgets.json`. שומרים את זה
  בקומיט נפרד.

## לחריגות יש תפוגה

כלל עם `expires` ‏(YYYY-MM-DD) הוא חריגה, והוא חייב לציין גם את המשימה
(`task`) שמסירה אותו. היום יש אחת: מודול הליבה של Excalidraw ב־740 KB, עד
2027-01-15, ו־W1.36 מסירה אותה. מהיום שאחרי התאריך `npm run budget` נכשל
עד שמורידים את הכלל או מחליטים עליו מחדש עם תאריך חדש, ו־pr:check מכשיל
תאריך מאוחר יותר. כדי לבדוק בנייה ביום אחר, מגדירים `LUMEN_TODAY=YYYY-MM-DD`.

## שום העלאה לא נכנסת

- ‏`npm run pr:check` מכשיל שינוי שמרפה אחד משלושת הקבצים. הוא משווה את
  התקציב שכל שם chunk מקבל לפני ואחרי, ולכן נספרים מספר שעלה, כלל חדש
  רחב יותר מזה שהקבצים שלו היו תחתיו, כלל שהוסר והקבצים שלו נופלים לכלל
  גדול יותר, ושינוי סדר. נספרים גם תאריך תפוגה מאוחר יותר או שנמחק, מרווח
  רחב יותר, סף ביצועים שעלה, הוסר או הפך מ־`error` ל־`warn`, פחות ריצות,
  ורמה או ציון נמוכים יותר ב־Lighthouse. גם מספר תקציב שנכתב בתוך
  `scripts/bundle-budget.mjs` עצמו נכשל.
- ‏`npm run budget:history` בודק כל קומיט של שלושת הקבצים מאז שה־ratchet
  התחיל, ומציין כל קומיט שהעלה גבול. עם `-- --since all` רואים את כל
  ההיסטוריה, כולל ההחלטות שהתקבלו לפני ה־ratchet.

כשתקציב נכשל, מפצלים את ה־chunk או טוענים אותו בעצלות. התקציב לא עולה.
