הממשק של Lumen בשמונה שפות. כשמוסיפים מחרוזת באנגלית, גם שבע האחרות
(עברית, ערבית, גרמנית, צרפתית, יפנית, רוסית, סינית מפושטת) צריכות אותה.
במקום להשאיר אותן ריקות, מכינים טיוטות:

```sh
npm run i18n:draft
```

הפקודה מוצאת כל מפתח אנגלי שחסר בשפה, מתרגמת אותו עם מודל **על המחשב
שלכם** (Ollama), כותבת את הטיוטות ל-`src/i18n/locales/<lang>/<domain>.json`
ורושמת כל אחת ב-`i18n/needs-review/<domain>.json`. עשרה מפתחות חדשים נותנים
שבעים טיוטות בהרצה אחת.

## אפשרויות

| אפשרות | מה היא עושה |
| --- | --- |
| `--keys=a.b,c.d` | רק המפתחות האלה |
| `--lang=he,ar` | רק השפות האלה |
| `--model=qwen2.5:7b` | מודל ה-Ollama (`OLLAMA_HOST` קובע את הכתובת, ברירת מחדל `http://127.0.0.1:11434`) |
| `--engine=fake` | בלי מודל: כותב `[he] English text` — הרצת ניסיון |
| `--list` | מה עוד ממתין לבדיקה, לפי שפה |
| `--approve=he [--keys=…]` | מסמן את הטיוטות בעברית (או רק את המפתחות האלה) כבדוקות |

מעבירים אפשרויות אחרי `--`: `npm run i18n:draft -- --keys=toolbar.save`.

## מה נבדק

- כל `{placeholder}` וכל `` `קוד` `` מוחלפים באסימון שהמודל חייב לשמור.
  טיוטה שמאבדת, משכפלת או ממציאה אסימון **לא נכתבת** ומדווחת.
- שפה שכבר יש בה את המפתח לא משתנה; הרצה חוזרת לא מתרגמת פעמיים.

## בדיקה

האפליקציה מציגה טיוטה מיד, אבל שער הערכים
(`src/__tests__/i18nValues.test.ts`) סופר כל טיוטה רשומה כ**לא מתורגמת**:
בעברית אסור אף אחת, בשאר השפות עד 5%. קוראים את הטיוטות, מתקנים בקובץ
השפה מה שצריך, ואז מאשרים:

```sh
npm run i18n:draft -- --approve=he
```

כל רשומה ב-`needs-review` שומרת גיבוב של הטקסט האנגלי שממנו נוצרה הטיוטה,
כך שאפשר לזהות טיוטה שהאנגלית שלה השתנתה מאז.

## מנועים

Ollama הוא המנוע כיום. התרגום על המכשיר של תוכנית 6.4 (Translator של
Chrome, ‏Opus-MT, ‏M2M100) רץ בדפדפן; הוא מתחבר כמנוע נוסף דרך אותו ממשק
`translate(texts, lang)` (`scripts/lib/i18n-draft.mjs`).
