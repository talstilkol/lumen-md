ב־Lumen נהגנו לערום pull requests: הבסיס של כל PR היה הענף של ה־PR שמתחתיו.
בנובמבר 2026 היו 322 מתוך 330 ה־PR־ים הפתוחים מוערמים, על 175 בסיסים שונים,
בעומק של עד 58. המחיר: היסטוריות כפולות (ענף אחד נשא 1,398 קומיטים מהיסטוריה
שהוחלפה), מיזוגי criss-cross, וכ־50 פתרונות ידניים ברכבת 2. מעכשיו (תוכנית W6.22):

- **הבסיס הוא ראש הרכבת או `main`.** הרכבת הנוכחית היא ענף ה־`verify/train-N`
  עם המספר הגבוה ביותר בשרת (היום `verify/train-2`). לא ענף `feat/*`, ולא
  רכבת ישנה.
- **להישאר קרוב אליו.** לפני הרכבת ממזגים את ראש הרכבת לתוך הענף, או
  מעבירים אותו (restack).
- **להישאר צעיר.** ענף שבסיס המיזוג שלו עם הבסיס בן יותר מ־7 ימים לא
  מעודכן. מעדכנים אותו או סוגרים אותו.
- **עומק הערימה הוא לכל היותר 1.** אם העבודה צריכה קוד של PR אחר, מחכים
  שה־PR הזה ייכנס לרכבת, ואז מבססים את שלכם על הרכבת.

## מה pr:check אומר

ל־`npm run pr:check -- --base origin/<base>` יש סעיף **Based on the train head**:

| ממצא | תוצאה |
|---|---|
| הבסיס הוא הרכבת הנוכחית או `main` | תקין |
| הבסיס הוא כל דבר אחר (PR מוערם) | אזהרה, עם פקודת ה־restack |
| הענף מאחורי הבסיס שלו (ראש הרכבת, כשהוא מוערם) | אזהרה, עם מספר הקומיטים |
| בסיס המיזוג בן יותר מ־7 ימים (`--max-age-days`) | **נכשל** |
| יותר מבסיס מיזוג אחד (criss-cross) | **נכשל** |

‏`--train <branch>` מציין את הרכבת כשה־`verify/train-N` הגבוה ביותר הוא לא
הנכון, למשל בזמן שבונים את הרכבת הבאה.

## העברת PR מוערם: scripts/restack.mjs

```bash
node scripts/restack.mjs --branch feat/my-thing --base feat/the-base
node scripts/restack.mjs --pr 412
node scripts/restack.mjs --all            # כל PR פתוח שלא על הרכבת או על main, הורים קודם
```

זו הרצה יבשה. היא קוראת את git ואת GitHub ולא משנה דבר. לכל PR היא מדפיסה
אחד מאלה:

- **→ הפקודות.** היא מריצה מחדש רק את הקומיטים של הענף עצמו (`base..branch`)
  על ראש הרכבת, לתוך ענף חדש `restack/<branch>`, ואז מריצה את pr:check ודוחפת.
  קומיטים שכבר ברכבת לפי patch מדולגים. קומיטי מיזוג נשמרים עם
  `--rebase-merges`. שום דבר לא נדחף בכוח, והבסיס של אף PR לא משתנה: פותחים
  PR חדש מ־`restack/<branch>` שכתוב בו "Supersedes #N".
- **✗ חסום.** העבודה של הבסיס הישן עוד לא ברכבת, והענף היה מאבד קוד שהוא
  נשען עליו. מעבירים קודם את הבסיס, או מחכים שייכנס לרכבת.
- **✓ אין מה לעשות.** ה־PR כבר על הרכבת או על `main`.
- **? לא נמשך.** מריצים שוב עם `--fetch`, או מושכים את הענפים שהיא מציינת.

מריצים את `--all` פעם בשבוע, אחרי שהרכבת השבועית נחתכת, כדי שכל PR שעדיין
פתוח יעבור לרכבת החדשה.

‏clone רדוד לא מוצא בסיסי מיזוג: מעמיקים אותו קודם
(`git fetch --deepen=500 origin <branch>`).
