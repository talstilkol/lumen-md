רכבת היא ענף אינטגרציה, `verify/train-N`. היא מתחילה מראש הרכבת הקודמת
וממזגת את ה־PR־ים המוכנים לפי מספר עולה. ‏Vercel בונה אותה עם כל השערים,
ואחרי שכולם עוברים `main` זז אליה. רכבות 1 ו־2 נבנו ביד. ברכבת 2 היו 110
PR־ים, ו־`main` לא זז 26 יום. מרכבת 3 והלאה (תוכנית W6.42) התהליך כתוב
בסקריפט, והרכבת קטנה ושבועית.

## הכללים

- **לכל היותר 15 PR־ים ברכבת שבועית.** רכבת השלמה (רכבת 3, עם 31) אומרת
  את זה עם `--max`.
- **כל PR מבוסס על ראש הרכבת** (ראו [כל PR על ראש הרכבת](/he/contributing/train-base/)),
  ולכן הוא נכנס בלי ערימה.
- **לכל היותר 10 פתרונות ידניים לרכבת.** היומן סופר אותם.
- **דוחפים את הרכבת פעם אחת** כשהיא שלמה, ולכל היותר דחיפת תיקון אחת
  (‏Vercel Hobby מתיר 100 פריסות ביום).
- בכל כותרת קומיט יש `[skip ci]`. ‏PR ‏#109 (הדומיין הישן) לעולם לא נכנס.
  רק טל ממזג ל־`main`.

## השבוע

| מתי (שעון ישראל) | מה | פקודה |
|---|---|---|
| ראשון | חותכים את הרכבת: סטטוס, ואז בנייה | `npm run train:status`, `npm run train:build -- --train verify/train-N --onto origin/verify/train-<N-1> --from-api` |
| ראשון | דוחפים פעם אחת. פותחים את PR הרכבת `verify/train-N → verify/train-<N-1>` | `git push -u origin verify/train-N` |
| שני–שלישי | קוראים את תוצאת Vercel (build, ‏budget, ‏vitest, ‏e2e, ‏i18n, ‏hygiene, ‏docs, רישיונות, סודות). מתקנים בדחיפה אחת לכל היותר. מריצים את קבלת הלילה על הראש ואת תרגיל הנתונים | `npm run nightly -- --commit` |
| רביעי | מורידים את התקציבים למה שהרכבת מדדה (ה־ratchet של התקציב, תוכנית W6.26). מעבירים כל PR שעדיין פתוח לרכבת החדשה (תוכנית W6.22) | `node scripts/budget-ratchet.mjs --sizes-log <build log> --write`, `node scripts/restack.mjs --all` |
| חמישי | טל מקדם את `main` לרכבת כש־`train:status` מראה ✓ בכל השערים | — |

אם שער עדיין אדום ביום חמישי, ה־PR ששובר אותו יוצא מהרכבת: בונים אותה
מחדש בלעדיו (`--exclude <n>`), והוא נכנס לרכבת של השבוע הבא. ‏`main` לא
מחכה ל־PR אחד.

## npm run train:build

```bash
npm run train:build -- --train verify/train-3 --onto origin/verify/train-2 --prs 464-494 --max 31
npm run train:build -- --train verify/train-4 --onto origin/verify/train-3 --from-api
npm run train:build -- --continue
```

מריצים אותו ב־worktree משלו. הוא עובר ל־`--train`, ויוצר אותו ב־`--onto` אם
צריך. אחר כך הוא ממזג כל PR עם `git merge --no-ff` והכותרת
`Merge #N branch [skip ci]`, ומדלג על מה שכבר בפנים. ‏`--prs` מקבל מספרים
וטווחים, ‏`--list` קובץ של שורות "number branch", ו־`--from-api` את כל
ה־PR־ים הפתוחים שהבסיס שלהם הוא הרכבת הקודמת או `main`, הוותיק קודם.
‏`--dry-run` רק מדפיס את התור. הוא אף פעם לא דוחף.

בקונפליקט הוא מריץ את הפותר (`scripts/train/resolve.mjs`):

| קובץ | פתרון |
|---|---|
| `i18n/keys.json` | נוצר מחדש מהמקורות הממוזגים |
| השינוי של theirs כבר נמצא ב־ours | ours |
| `eval/baseline/*` | theirs |
| `*.json` | מיזוג תלת־כיווני לפי מפתח; מערכים כאיחוד |
| imports עם שמות בשני הצדדים | ממוזגים לפי מודול; מה שהוסר נשאר מוסר |
| שני הצדדים רק הוסיפו שורות | ours ואחריו theirs, עם שורות הסגירה המשותפות מוחזרות איפה שהמנתח צריך אותן |
| שני הצדדים שינו את אותן שורות | ה־hunks של theirs מועברים אל ours (`scripts/train/port.mjs`), גם לקובץ ש־ours העביר אליו את הקוד |
| כל דבר אחר | **MANUAL**: נשאר עם סימני diff3 |

אחר כך הוא מריץ את `scripts/train/check.mjs` על ה־TypeScript שהמיזוג נגע
בו. הבדיקה מוצאת שגיאות תחביר, פונקציה שהאיחוד הכריז עליה פעמיים, imports
שלא בשימוש, import בשם שהמודול לא מייצא, ושם שלא הוכרז בשום מקום. כשהפותר
או הבדיקה צריכים אדם, המיזוג נשאר פתוח ושורות ה־MANUAL אומרות אילו קבצים.
פותרים אותם לפי משמעות (קוראים את שני הצדדים ושומרים את שתי ההתנהגויות;
‏`git checkout --conflict=diff3 <file>` מחזיר את הסימנים), מריצים
`git add` ואז `--continue`.

כל קומיט מיזוג מסתיים ב־trailer: ‏`Train-Resolution: clean`, ‏`auto` או
`manual`, עם הקבצים. זה היומן.

## npm run train:status

```bash
npm run train:status
npm run train:status -- --train verify/train-3 --no-api
```

הוא מדווח על הרכבת הנוכחית (ה־`verify/train-N` הגבוה ביותר): הראש שלה,
הגיל שלה וכמה היא לפני `main`. הוא מדווח על היומן מאז הרכבת הקודמת (נקי,
בידי הפותר, ביד; היעד: לכל היותר 10 ביד) ועל הפעם האחרונה ש־`main` זז
(היעד: בתוך 7 ימים), עם החיתוך הבא. הוא מראה את השערים של הראש: הסטטוס של
Vercel, קבלת לילה שנשמרה בקומיט עבור הקומיט הזה, ותרגיל הנתונים, שנעשה
ביד. הוא גם מציג את התור (PR־ים פתוחים על הרכבת או על `main` שעוד לא בה)
ואת הגיל החציוני של ה־PR־ים הפתוחים שהיא נושאת (היעד: עד 7 ימים ל־`main`).
שורת אזהרה מציינת כל יעד שלא הושג.

## במה המחזור נמדד

- ‏`main` זז לפחות פעם בשבוע, ארבעה שבועות ברצף.
- הזמן החציוני מ־PR ל־`main` הוא לכל היותר 7 ימים.
- לכל היותר 10 פתרונות ידניים לרכבת שבועית.
