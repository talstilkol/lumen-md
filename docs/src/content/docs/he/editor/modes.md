ל-Lumen ארבעה משטחי עריכה. מחליפים ביניהם עם `⌘1` / `⌘2` / `⌘3` / `⌘4`.

## מקור (`⌘1`)

‏CodeMirror 6 רגיל עם הדגשת Markdown. משתמשים בו כשרוצים לכתוב מהר, לראות
בדיוק מה יש בקובץ, או להדביק Markdown מעוצב מראש. כפתור ״הוספה חכמה״
(`⌘⇧V`) חזק במיוחד כאן.

**הכי מתאים**: לכותבים שחושבים ב-Markdown; לפתקים עתירי נתונים שבהם רוצים
לראות את תוחמי הגדרות.

## מפוצל (`⌘2`, ברירת מחדל)

עורך בצד אחד, תצוגה חיה בצד השני. כיוון הפיצול הולך לפי המסך — אופקי במסכים
רחבים, אנכי בטלפונים. אפשר לשנות דרך תפריט **Scroll orientation** בסרגל
העליון.

גלילה מקושרת פעילה כברירת מחדל — שתי החלוניות עוקבות אחרי אותה כותרת גם
כשגובה התוכן שונה.

**הכי מתאים**: לרוב סשני הכתיבה. רואים את התוצאה המעובדת ברגע שמקלידים.

## תצוגה (`⌘3`)

עיבוד לקריאה בלבד של ה-Markdown. טבלאות, גרפים, תרשימים, מתמטיקה, הטמעות —
הכול בצורתו הסופית. מדפיסים מכאן עם `⌘K → Print / Save as PDF…`, ששומר על
הצבעים כך שקובצי PDF יוצאים נאמנים.

**הכי מתאים**: לקריאה חוזרת, הגהה, שיתוף מסך.

## WYSIWYG ‏(`⌘4`)

עריכה ברמת Notion מעל Milkdown / ProseMirror. תפריט לוכסן (`/`), מתמטיקה
בשורה, סידור בלוקים בגרירה. חוזר ל-Markdown רגיל — כך שמסמך שנכתב ב-WYSIWYG
נפתח נקי במצב מקור.

**הכי מתאים**: לחושבים ויזואלית; למסמכים עשירים (מצגות); למי שעובר מ-Notion.

## מצב הצעות (מעקב שינויים)

מפעילים אותו מלוח הפקודות (״Turn on suggesting mode (track changes)״) או
מכפתור **Editing / Suggesting** בשורת המצב. כשהוא פעיל, עריכות בעורך המקור /
המפוצל וב-WYSIWYG נרשמות כ-[CriticMarkup](https://github.com/CriticMarkup/CriticMarkup-toolkit),
כך שהקובץ נשאר Markdown רגיל:

| מה עושים | איך זה נשמר |
| --- | --- |
| מקלידים טקסט | `{++inserted++}` |
| מוחקים טקסט (Backspace, ‏Delete, גזירה) | `{--deleted--}` |
| מקלידים מעל בחירה | `{~~old~>new~~}` |
| כותבים הערה ביד | `{>>comment<<}` / `{==highlight==}` |

- הקלדה ליד הוספה שלכם מאריכה אותה, ומחיקות רצופות מתאחדות. מחיקת טקסט בתוך
  `{++ ++}` שלכם באמת מוחקת אותו.
- ביטול / ביצוע מחדש, עריכות של משתתפים אחרים, ועריכות בתוך בלוקי קוד או קוד
  בשורה לעולם לא הופכים להצעות.
- העורך מציג הוספות עם קו תחתון ירוק, מחיקות עם קו חוצה אדום והערות מודגשות;
  התצוגה מציגה אותן כ-`<ins>`,‏ `<del>` ו-`<mark>`.
- פקודות בלוח: קבלה / דחייה של ההצעה שבסמן, קבלת הכול, דחיית הכול, ההצעה
  הבאה / הקודמת. כולן עובדות גם ב-WYSIWYG; קבלת הכול / דחיית הכול עובדות גם
  ממצב תצוגה.
- **ב-WYSIWYG** ההצעות מוצגות כהוספות עם קו תחתון ומחיקות עם קו חוצה (ריחוף
  מציג את הכותב). הקלדה נרשמת כהוספה, Backspace / Delete משאירים את הטקסט עם
  קו חוצה ומדלגים עליו, והקלדה מעל בחירה הופכת להחלפה. עריכות מבניות — חיבור
  שתי פסקאות עם Backspace — לא נרשמות כהצעה ומבוטלות; כבו את מצב ההצעות בשביל
  אלה.
- הכפתור בשורת המצב מראה כמה הצעות יש במסמך.
- **מי הציע.** כשאתם מחוברים, אחרי כל הצעה חדשה מופיע תג כותב — הערה שמכילה
  רק `@name`, למשל `{++new text++}{>>@Tal<<}`. התג שייך לשינוי שלו: קבלה או
  דחייה של השינוי מסירה גם אותו. ריחוף מעל הצעה מציג ״Suggested by …״;
  התצוגה מציגה את השם כהערה קטנה. הקלדה בתוך הצעה של מישהו אחר שומרת עליה את
  השם שלו.

## בדיקות TypeScript בבלוקי קוד

מריצים **Enable TypeScript checks in code blocks** מלוח הפקודות. בעורך
המקור / המפוצל, כל בלוק ` ```ts `,‏ ` ```typescript ` ו-` ```tsx ` (ובלוקי
JavaScript, ראו בהמשך) נבדק אז על ידי המהדר האמיתי של TypeScript:

- שגיאות מקבלות קו תחתון גלי — ריחוף מציג את ההודעה (`TS2322: …`).
- ריחוף מעל שם מציג את הטיפוס שלו (ואת ה-JSDoc, אם יש).
- השלמות קופצות תוך כדי הקלדה (אחרי `.` או כמה אותיות; `Ctrl-Space` מכריח
  אותן).
- כל בלוק נבדק בנפרד (ההצהרות שלו לא דולפות לבלוקים אחרים), במצב strict מול
  הספריות ES2022 ו-DOM. ייבוא של חבילות npm לא נפתר ולא מדווח.
- בלוקי JavaScript ‏(` ```js `,‏ ` ```javascript `,‏ ` ```live-js `) מקבלים
  שגיאות תחביר, ריחוף והשלמות; מוסיפים `// @ts-check` בשורה הראשונה כדי לקבל
  גם שגיאות טיפוסים.
- בלוקי ` ```live-js shared ` נבדקים יחד לכל scope ‏(`shared=name`), לפי סדר
  המסמך — בלוק מאוחר רואה את השמות שבלוק מוקדם הצהיר, בדיוק כמו בהרצה. מותר
  שם להצהיר שוב על שם.

המהדר (כ-1.3 MB דחוס) רץ ב-worker ברקע ומורד רק אחרי שמפעילים את ההגדרה; הוא
לא חלק מקליפת האפליקציה שעובדת בלי רשת. ההגדרה נזכרת.
