עורך Markdown לא אמור לשכתב לכם קבצים בלי לשאול. Lumen נבדק מול המפרטים
הרשמיים, וגם מול הלוך-ושוב משלו: פותחים קובץ, שומרים, ומקבלים בדיוק את
הבתים שהיו בו.

## עמידה במפרט

המפענח של Lumen נבדק מול דוגמאות המפרט הרשמיות. הקבצים שמורים במאגר כמו
שהם, בלי שינוי:

| חבילה | דוגמאות | סף |
|---|---|---|
| CommonMark 0.31.2 | 652 | לפחות 99% |
| GitHub Flavored Markdown 0.29 | 670 (2 מושבתות במקור) | לפחות 98% |

המפענח שמתחת (micromark) עובר לבדו את כל דוגמאות CommonMark. מה ש-Lumen
מוסיף מעליו משנה בכוונה כמה תוצאות:

| איפה Lumen שונה | למה |
|---|---|
| בלוק `---` בתחילת הקובץ הוא frontmatter | הוא מחזיק את המטא-דאטה של הפתק (כותרת, תגיות). המפרט קורא אותו כקו מפריד וטקסט. |
| כתובת URL או דוא"ל חשופים הופכים לקישור | הקישור האוטומטי של GFM פעיל תמיד, גם בדוגמאות שבודקות CommonMark נקי. |
| כתובות `ftp://` לא מקושרות אוטומטית | כמו ב-github.com היום. כדי לקשר, כתבו `<ftp://…>`. |
| המפענח לא מסנן HTML גולמי אסור (`<script>`, `<title>` וכו') | התצוגה המקדימה מנקה את כל ה-HTML הגולמי אחר כך, וזה מסיר את התגיות האלה. |
| ירידת שורה בודדת בתוך פסקה מוצגת כירידת שורה | הגדרת ירידת השורה הרכה של התצוגה המקדימה. היא לא חלק מהציון שנבדק בסף. |

מפרט GFM נעול על CommonMark 0.29. במקומות שבהם CommonMark 0.31.2 שינה את
התוצאה הצפויה לאותו קלט (בעיקר כללי ההדגשה), Lumen הולך לפי המפרט החדש,
והדוגמאות האלה לא נספרות בציון של GFM.

כל דוגמה אחרת שנכשלת מכשילה את החבילה, כך שכל הבדל חייב הסבר כאן.

## הלוך ושוב

שני העורכים נבדקים על יותר מ-200 קובצי Markdown אמיתיים: כל מה שיש במאגר,
כולל התיעוד בעברית, וכל פרק של שני קובצי המפרט. מעליהם מתווסף עותק CRLF של
כל קובץ עשירי.

- **עורך המקור:** פתיחה ושמירה מחזירות בדיוק את אותם בתים, בכל קובץ. קובץ
  עם סופי שורה של Windows ‏(CRLF) נשאר CRLF. קובץ עם סופי שורה של Mac הישן
  ‏(CR) נשאר CR. בקובץ עם סופי שורה מעורבים, תווי ה-CR הבודדים נשארים במקומם
  ומוצגים כסימן תו מיוחד.
- **WYSIWYG:** בלוקים שלא נערכו נשמרים בדיוק כמו שהיו בקובץ. עריכה כותבת
  מחדש רק את הבלוק ששיניתם, למשל את הפסקה, הרשימה או הטבלה שהקלדתם בה. כל
  השאר שומר על הסגנון שלו: תבליטי `*` או `-`, ‏`__bold__` או `**bold**`,
  ריפוד הטבלאות והשורות הריקות. בלוקים ש-WYSIWYG לא מציג, כמו הגדרות של
  קישורי הפניה, נשמרים במקומם. בקובץ CRLF, גם הבלוקים שאתם מוסיפים מקבלים
  CRLF.

## לבדוק בעצמכם

```sh
npm run md:conformance
```

הפקודה מריצה את חבילת העמידה במפרט, את ההלוך-ושוב בשני העורכים, ואת
בדיקות היחידה של השמירה ששומרת על המקור. התוצאות המלאות, כולל כל דוגמה
שנכשלה והשוואה לכל קובץ של הסריאליזציה של WYSIWYG, נכתבות אל
`test-results/md-conformance/` ואל `test-results/md-roundtrip/`.
