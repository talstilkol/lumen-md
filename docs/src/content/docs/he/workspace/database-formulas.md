בלוק `database` יכול להוסיף **עמודות נוסחה**: ערכים שמחושבים מה-frontmatter
של כל פתק. הן מופיעות בכל תצוגה, ואפשר לסנן, למיין ולקבץ לפיהן כמו לפי כל
מאפיין אחר.

```database
source: shop/
type: item
formulas:
  total: price * qty
  big: total >= 100          # a formula can use the ones above it
  late: if(due < today() and status != "done", "late", "")
  שנה: year(תאריך)
```

כל עמודות הנוסחה מוצגות: כשיש `fields:` במפרט, עמודות הנוסחה שלא רשומות שם
באות אחרי השדות הרשומים (רשמו עמודה ב-`fields:` כדי למקם אותה במקום אחר).
תאים של נוסחה הם לקריאה בלבד (הם לא נכתבים לפתקים). פתק שנוסחה לא מצליחה
לחשב בשבילו — למשל `price: "n/a"` בנוסחה `price * qty` — מציג **error**
באותו תא, והסיבה מופיעה במעבר עכבר; שאר הפתקים לא מושפעים.

## לנסות נוסחה

לחצו על **ƒ Formula column** מעל התצוגה, תנו לעמודה שם והקלידו נוסחה: היא
נבדקת תוך כדי הקלדה, ו-**Add column** מציג אותה מיד. כדי לשמור אותה, העתיקו
את השורה שמוצגת אל `formulas:` של הבלוק.

**Write with AI** הופך תיאור ("כמה ימים נשארו עד תאריך היעד, וכלום כשהמשימה
הסתיימה") לנוסחה, בעזרת המודל המקומי (Ollama או המודל שבדפדפן). התשובה
נבדקת באותו מפענח: נוסחה שלא מתפענחת, שקוראת לפונקציה לא מוכרת או שמשתמשת
במאפיין שאין במסד הנתונים נשלחת חזרה למודל עם השגיאה, כך שמה שמתקבל תמיד
מתפענח.

## תחביר

| | |
|---|---|
| מספרים | `12`, `3.5`, `.5`, `1e3` |
| טקסט | `"text"` או `'text'`; בפנים `\"` ו-`\\` |
| כן / לא / כלום | `true`, `false`, `null` |
| רשימות | `[1, 2, 3]` |
| מאפיינים | `price`, `תאריך`, `meta.owner`; ‏`prop("due date")` לשמות עם רווחים או סימנים |
| הפתק עצמו | `file.name`, `file.path`, `file.folder` |
| חשבון | `+ - * / %`, ‏`^` (חזקה, מימין לשמאל: `2 ^ 3 ^ 2` הוא 512) |
| חיבור טקסט | `&`, או `+` כשאחד הצדדים הוא טקסט רגיל |
| השוואה | `=` (`==`), ‏`!=` (`<>`), ‏`<`, ‏`<=`, ‏`>`, ‏`>=` — לא בשרשור (`a < b < c` היא שגיאה) |
| לוגיקה | `and` / `&&`, ‏`or` / `||`, ‏`not` / `!` |

סדר הקדימות, מהחלש לחזק: `or`, ‏`and`, ‏`not`, השוואה, `&`, ‏`+ -`,
‏`* / %`, מינוס אונרי `-`, ‏`^`. מילות מפתח ושמות פונקציות לא תלויים
באותיות גדולות וקטנות.

**ערכים** מתנהגים לפי הכללים של המסנן: מספרים נשארים מספרים, טקסט מספרי
(`"12"`) נחשב מספר, טקסט בצורה `YYYY-MM-DD` מושווה כתאריך, רשימה שווה לערך
שהיא מכילה (`tags = "fav"`), ‏`=` משווה טקסט בלי להתחשב באותיות גדולות
וקטנות, ו-`<` / `>` מסדרים טקסט לפי קוד התו — אותה תוצאה בכל הגדרת שפה
(סדר אלפביתי בעברית; אותיות גדולות לפני קטנות). מאפיין ריק הופך חשבון לריק
(`price * qty` בלי `qty` הוא ריק, לא שגיאה). ‏`0.1 + 0.2` הוא `0.3`.

**תאריכים** הם ב-UTC, כך שנוסחה נותנת אותה תשובה בכל אזור זמן: `2026-10-20`
הוא חצות UTC, וגם שעה שנכתבה בלי היסט (`2026-10-20T12:00`) נקראת כ-UTC.
‏`date + 7` ו-`date - 7` זזים בימים; ‏`date - date` הוא מספר הימים ביניהם.

## פונקציות

**לוגיקה**

- `if(condition, then, else?)` — ‏`then` כשהתנאי מתקיים, אחרת `else` (ריק כשהוא לא ניתן). רק הענף שנבחר מחושב.
- `and(a, b, …)`, ‏`or(a, b, …)`, ‏`not(x)`
- `coalesce(a, b, …)` (או `ifempty`) — הארגומנט הראשון שאינו ריק
- `empty(x)` — אין ערך, טקסט ריק או רשימה ריקה
- `prop("name")` — המאפיין ששמו name

**טקסט**

- `concat(a, b, …)` — מחוברים כטקסט
- `len(x)` (או `length`) — מספר התווים בטקסט (כל אות עברית נספרת פעם אחת), מספר הפריטים ברשימה
- `upper(text)`, ‏`lower(text)`, ‏`trim(text)`
- `contains(textOrList, value)` — בלי להתחשב באותיות גדולות וקטנות; ברשימה — האם היא מכילה את הערך
- `startswith(text, prefix)`, ‏`endswith(text, suffix)` — בלי להתחשב באותיות גדולות וקטנות
- `replace(text, find, with)` — כל ההופעות; טקסט רגיל, לא תבנית
- `slice(text, start, end?)` (או `substring`) — מתחיל מ-0; מספר שלילי סופר מהסוף
- `left(text, n)`, ‏`right(text, n)`, ‏`repeat(text, n)`
- `join(list, separator?)` — ‏`", "` אם לא ניתן אחר; ‏`split(text, separator)` — רשימה
- `text(x)` — כטקסט (תאריכים כ-`YYYY-MM-DD`); ‏`number(x)` — כמספר, ריק כשזה לא מספר

**מתמטיקה**

- `abs(x)`, ‏`floor(x)`, ‏`ceil(x)`, ‏`sqrt(x)`, ‏`pow(x, y)`, ‏`mod(x, y)`
- `round(x, digits?)` — חצאים מתעגלים הרחק מאפס; ‏`round(1.005, 2)` הוא `1.01`
- `min(…)`, ‏`max(…)`, ‏`sum(…)`, ‏`avg(…)` (או `average`), ‏`count(…)` — מספרים או רשימות של מספרים; ערכים ריקים מדולגים

**תאריכים**

- `today()`, ‏`now()`
- `date("2026-10-20")`, ‏`date(2026, 10, 20)`
- `year(d)`, ‏`month(d)` (1–12), ‏`day(d)`, ‏`weekday(d)` (1 = ראשון … 7 = שבת)
- `dateadd(d, n, unit?)` — היחידה `"days"` (ברירת מחדל), ‏`"weeks"`, ‏`"months"`, ‏`"years"`, ‏`"hours"`, ‏`"minutes"`; ‏31 בינואר ועוד חודש הוא 28 בפברואר
- `datediff(later, earlier, unit?)` — מספר היחידות השלמות מהמוקדם למאוחר (חודש נספר כשמגיעים ליום שלו)

## שגיאות ומגבלות

כל בעיה מדווחת כשגיאת נוסחה, עם התו שבו היא נמצאת: שגיאת תחביר, פונקציה לא
מוכרת, מספר ארגומנטים שגוי, ערך מסוג לא נכון (`"a" * 2`), או חשבון שאין לו
תשובה (חלוקה באפס, `sqrt(-1)`, מספר גדול מדי).

נוסחאות רצות במפרש של Lumen עצמו, על קבוצה קבועה של פעולות ועל הפונקציות
שלמעלה — אף פעם לא כ-JavaScript, כך שנוסחה לא יכולה להגיע לשום דבר מלבד
ה-frontmatter של הפתק. לכל נוסחה יש מגבלות קבועות, שנספרות בצעדים ולא בזמן,
כך שהיא תמיד מסתיימת ואותה נוסחה תמיד מתנהגת באותו אופן:

| מגבלה | ערך |
|---|---|
| אורך נוסחה | 2,000 תווים |
| קינון (סוגריים, קריאות, אופרטורים משורשרים) | 64 רמות |
| חלקים בנוסחה | 1,000 |
| צעדים לפתק אחד | 20,000 |
| אורך ערך טקסט | 20,000 תווים |
| פריטים בערך רשימה | 2,000 |

פונקציות נוסחה שתוספים מגדירים (ורצות בארגז חול של QuickJS) מתוכננות; הן
יתווספו לרשימה הזו בלי לשנות את הפונקציות המובנות.

## תצוגת מפה

הלשונית **Map** מציבה על מפה כל פתק שיש לו קואורדינטות (אריחי OpenStreetMap;
‏Leaflet נטען רק כשפותחים את הלשונית). הקואורדינטות של פתק נלקחות מ:

- המאפיין שנקבע ב-`location:` במפרט, ואם אין כזה
- מאפיין `location` (או `coordinates`), ואם אין כזה
- מאפייני `lat` (או `latitude`) ו-`lng` (או `lon`, ‏`longitude`).

אפשר לכתוב מיקום כ-`"32.08, 34.78"`, ‏`[32.08, 34.78]` או
`{lat: 32.08, lng: 34.78}`. לחיצה על סמן מציגה את כותרת הפתק (שפותחת אותו)
וכמה מהשדות שלו. פתקים בלי קואורדינטות נספרים מתחת למפה.

```database
source: trips/
view: map
location: place
fields: [date, rating]
```
