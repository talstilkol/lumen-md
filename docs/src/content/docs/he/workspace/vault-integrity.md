הפתקים שלכם הם קבצים אמיתיים. שמירה שנעצרת באמצע — הסוללה נגמרת, המערכת
סוגרת את האפליקציה, המחשב קורס — אסור שתשאיר פתק חצוי. Lumen דואג שזה לא
יקרה, ו**בדיקת כספת** מוצאת את מה שאפליקציות אחרות, תוכנות סנכרון או קריסה
ישנה השאירו.

## כל שמירה נכתבת בשלמותה

Lumen אף פעם לא כותב על פתק במקומו. הטקסט החדש נכתב קודם לקובץ מוסתר ליד
הפתק; רק כשכולו בדיסק, הקובץ הזה מקבל את שם הפתק. אם האפליקציה נעצרת
באמצע, בפעם הבאה שהיא פותחת את התיקייה היא משלימה את השמירה או מחזירה את
הגרסה הקודמת — כך שכל פתק הוא תמיד הגרסה שלפני השמירה או הגרסה שאחריה,
בשלמותה.

| איפה הכספת | איך |
|---|---|
| **אפליקציה למחשב** | קובץ זמני, `fsync`, שינוי שם מעל הפתק, ואז גם התיקייה מסונכרנת לדיסק. |
| **תיקייה ב-Chrome / Edge** | הדפדפן כותב קובץ החלפה ומחליף את הפתק כשהוא שלם. |
| **תיקייה בטלפון (iOS, Android)** | קובץ זמני `.lumen-tmp~…`, נבדק שהגודל שלו מלא, ואז שינוי שם; ב-Android הבתים נכתבים לדיסק קודם. |
| **אחסון הדפדפן ב-Safari** | אותם צעדים של קובץ זמני, בתוך ה-worker שכותב. |

שם של קובץ מחזיק עד 255 בתים, ואות עברית תופסת שניים. כשהשם הזמני של פתק
עם שם ארוך לא נכנס, השמירה משתמשת בשמות קצרים (`.lumen-tmp-<16 ספרות הקס>`)
וכותבת קודם יומן קטן (`.lumen-jnl-…`) שרושם לאיזה פתק הם שייכים. היומן נמחק
אחרון, כך שאפשר להשלים שמירה שנעצרה בכל שלב. אם היומן אבד, הגרסה הישנה
נשמרת, לא מחליפה שום פתק, ובדיקת התקינות מדווחת עליה.

זה נבדק בהריגת תהליך עם `kill -9` באמצע שמירה, 1,000 פעמים:
`npm run test:crash`. אחרי כל הריגה כל פתק שלם, והוא הגרסה הישנה או החדשה.

## בדיקת כספת

**לוח הפקודות ← בדיקת כספת** קורא כל קובץ בכספת (רק התיקיות שלכם — לא
`.git`, לא `.trash` ולא גיבויים קודמים) ופותח פתק דוח. הבדיקה מחפשת שנים־עשר
סוגי פגמים:

| בעיה | תיקון אוטומטי |
|---|---|
| קובץ שנקטע באמצע תו | כן — התו הקטוע מוסר |
| טקסט שאינו UTF-8 (למשל עברית שנשמרה ב-Windows-1255) | כן — מומר ל-UTF-8 |
| קובץ שנשמר ב-UTF-16 | כן — מומר ל-UTF-8 |
| בתים ריקים (NUL) בקובץ טקסט | כן — מוסרים |
| קובץ ריק | לא — מחזירים גרסה מהיסטוריית הפתק |
| קובץ נתונים JSON או YAML (`.canvas`, `.excalidraw`, `.base`, `.json`, `.yaml`) שאי אפשר לקרוא | לא |
| Front matter שלא נסגר או שאינו YAML תקין | לא |
| שני שמות באותה תיקייה שנבדלים רק באותיות גדולות/קטנות | כן — השני מקבל את השם `שם (2)` |
| שני שמות שנבדלים רק בצורת Unicode (é שנכתב בשתי דרכים) | כן — שינוי שם באותה דרך |
| קישור לפתק שלא קיים | לא — השתמשו ב**רופא הכספת: החלת תיקוני הקישורים המוצעים** |
| קובץ זמני של שמירה שנקטעה (של Lumen, של האפליקציה למחשב, `.crswap` של Chrome) | כן — נמחק |
| שמירה שנקטעה באמצע, והפתק חסר | כן — השמירה מושלמת, או שהגרסה הקודמת חוזרת |

שמות שנבדלים רק באותיות גדולות/קטנות חיים זה לצד זה ב-Linux ובאחסון
הדפדפן, אבל ב-macOS, ב-Windows ובטלפונים אחד מהם מסתיר את השני — וכך פתקים
הולכים לאיבוד כשכספת עוברת או מסתנכרנת.

כשיש מה לתקן, Lumen שואל פעם אחת ואז מתקן. **לפני שקובץ משתנה, מקבל שם
חדש או נמחק, הוא מועתק ל-`.lumen-repair/<תאריך ושעה>/`** בכספת, כך שאפשר
לבטל כל תיקון בהעתקת הקובץ חזרה. פתקים שפתוחים בלשונית לא נוגעים בהם, וקובץ
שהשתנה מאז הבדיקה לא משתנה.

הבדיקה הראשונה של כספת גדולה לוקחת זמן: 10,000 פתקים לקחו כעשר שניות
בדפדפן (נמדד ב-Chromium) ושתיים עד שלוש שניות מחוצה לו. אחר כך הבדיקה קוראת
שוב רק קבצים שהגודל או זמן השינוי שלהם השתנו, כך שאותם 10,000 פתקים לוקחים
פחות משנייה. קובץ שהשתנה בשניות שלפני בדיקה נקרא תמיד מחדש.
