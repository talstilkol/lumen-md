‏`⌘K` ← **סקירת ספרות מקובצי ה־PDF בכספת** קורא במכשיר הזה כל קובץ PDF
בכספת. עמודים סרוקים נקראים עם OCR. הפקודה כותבת:

- **פתק לכל מאמר** בתיקייה `Literature review/`, עם חמישה שדות כמאפיינים:
  שאלה, שיטה, מדגם, ממצאים ומגבלות. מתחת לכל ערך מופיעים הציטוטים שממנו
  הוא נלקח, כל אחד עם קישור לעמוד ולשורה שלו;
- **`Literature review.base`**, שמציג את הפתקים כטבלה: שורה לכל מאמר
  ועמודה לכל שדה (בפורמט Obsidian Bases). יש בו שתי תצוגות: **כל המאמרים**,
  ו**מאומתים בלבד**, שמציגה רק מאמרים שכל השדות שלהם אומתו.

## מפת טיעונים

תנו לפתקים `type: claim` (טענה) או `type: evidence` (מקור), וקשרו אותם ב-`supports:`,
‏`contradicts:` או `qualifies:` (כל אחד רשימה של `[[קישורים]]` לטענות). סמנו את
נקודות הסיום ב-`conclusion: true`. בלוק `argument-map` מצייר אותם:

```argument-map
folder: מחקר/שכר     # לא חובה
```

- המקורות בעמודה הראשונה (מימין בעברית), אחריהם הטענות שהם מובילים אליהן,
  ואחריהן המסקנות. קווים ירוקים תומכים, קווים אדומים מקווקווים סותרים, קווים
  צהובים מנוקדים מסייגים.
- טענה ששום מקור לא מגיע אליה דרך ״תומך״ או ״מסייג״ מסומנת **בלי מקור**.
- ״הצגה כרשימה״ נותנת את אותה מפה כרשימה מקוננת: כל טענה עם הפתקים שתומכים בה,
  סותרים אותה או מסייגים אותה. במפה, **Tab** אליה, ואז החצים עוברים מפתק לפתק
  ו-**Enter** פותח אחד.
- ״שמירה כקנבס״ כותבת את המפה ל-`canvases/` כ-JSON Canvas (נפתח ב-Obsidian)
  וכציור Excalidraw.
- שני הסוגים מובנים, ולכן הם מופיעים ברשימת הסוגים, ב-Base של הסוג ובטופס
  המאפיינים כמו הסוגים שלכם.

## אין ערך בלי ציטוט

לכל שדה, הקטעים שהחיפוש מוצא נשלחים למודל המקומי. המודל עונה עם ציטוטים
שהועתקו מהקטעים האלה. אחר כך כל ציטוט מחופש בקטע שלו ומאותר בעמוד שלו:

- ערך נשמר רק כשלפחות אחד מהציטוטים שלו נמצא.
- ציטוטים מומצאים, או ציטוטים שמפנים לקטע הלא נכון, נזרקים. אם לא נשאר
  אף ציטוט, השדה מציג „אין ערך עם ציטוט מאומת” במקום ניחוש.

המודל הוא המודל המקומי שבהגדרות הבינה המלאכותית (Ollama או המודל של
הדפדפן). מודל בענן משמש רק אם מדיניות ה־AI שבחרתם מתירה זאת.

## השערות מתחרות (ACH)

בלוק `ach` שוקל ראיות מול הסברים מתחרים, בשיטת ניתוח ההשערות המתחרות של
ריצ׳רדס הויר (Heuer):

```ach
title: מי הדליף את הדוח?
hypotheses:
  H1: מישהו מבפנים
  H2: קבלן
evidence:
  - text: הקובץ נושא שם של מחשב משרדי
    weight: 3
    marks: { H1: CC, H2: I }
  - text: פוסט בבלוג של הקבלן עצמו
    deceptive: true
    marks: { H1: N, H2: C }
```

- כל סימון הוא **CC** (מתיישבת מאוד), **C**, **N** (ניטרלית; תא ריק הוא N),
  **I** (סותרת) או **II**; גם `++ + 0 - --` עובדים. משקל הוא מספר שלם (ברירת
  מחדל 1).
- ההשערות מדורגות לפי הסתירה המשוקללת **הקטנה** ביותר (I = 1, ‏II = 2 לכל
  יחידת משקל): ראיות פוסלות השערות יותר משהן מוכיחות אותן. בתיקו מכריעה
  ההתאמה הגדולה יותר.
- הבלוק מראה גם אילו ראיות לא מבחינות בין ההשערות, באיזו ראיה אחת תלויה
  ההכרעה (ראיית מפתח), והאם המובילה עומדת בלי הראיות שסומנו `deceptive`.
- ״העתקה כטבלה״ מעתיקה את המטריצה כטבלת Markdown. זה כלי מחקר, לא פסק דין.

## איך זה נמדד

ב־`eval/probes/lit-review.json` יש חמישה מאמרים קצרים, באנגלית ובעברית.
לכל שדה רשומים בו העמוד הנכון וביטוי מתוכו.

- ‏`src/__tests__/litReview.test.ts` מריץ עליהם את החיפוש והאימות עם מודל
  מדומה. החיפוש מוצא את הקטע הנכון ל־24 מתוך 25 השדות, וכל ציטוט שנשמר
  נמצא בעמוד הנכון. הבדיקה גם מוודאת שממודל שממציא ציטוטים לא נשמר כלום.
- ‏`npm run eval:lit-review` מריץ את המודל האמיתי ומדווח איזה חלק מהשדות
  נכון.
- סט הקבלה הוא 20 מאמרים אמיתיים שהבעלים מספק באותו פורמט קובץ. היעדים של
  התוכנית: 85% מהשדות נכונים, וכל ציטוט בעמוד הנכון.
