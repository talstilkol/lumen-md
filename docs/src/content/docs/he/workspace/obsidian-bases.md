כספת שמגיעה מ-Obsidian שומרת את ה-**Bases** שלה: קובצי `.base` ‏(YAML)
שהופכים פתקים לטבלאות, כרטיסים, רשימות, לוחות קנבן ומפות. Lumen קורא וכותב
את אותם קבצים, כך שהתצוגות נשמרות במעבר לשני הכיוונים.

## שלוש דרכים להציג base

- **לפתוח את קובץ ה-`.base`** מסביבת העבודה: התצוגה המקדימה מראה את
  התצוגות שלו (לשונית לכל תצוגה). העורך עדיין מראה את ה-YAML.
- **להטמיע בפתק**: `![[Books.base]]` לבד בשורה, או
  `![[Books.base#Favourites]]` לתצוגה אחת.
- **לכתוב בתוך הפתק** בבלוק מגודר:

````markdown
```base
filters:
  and:
    - file.hasTag("book")
    - 'status != "read"'
formulas:
  hours: (pages / 50).round(1)
views:
  - type: table
    name: לקריאה
    order: [file.name, note.author, formula.hours]
    sort:
      - property: formula.hours
        direction: ASC
```
````

## מה נתמך

| חלק בקובץ | נתמך |
|---|---|
| `filters:` — ביטוי, או רשימות `and:` / `or:` / `not:` מקוננות | כן (`not:` מתקיים כשאף פריט בו לא מתקיים) |
| `formulas:` — מאפיינים מחושבים, `formula.<name>`, נוסחה יכולה להשתמש בנוסחה אחרת | כן (נוסחה שמפנה לעצמה מדווחת) |
| `properties:` — `displayName` לכותרות העמודות | כן |
| `summaries:` — נוסחאות סיכום משלך על `values` | כן |
| `views:` — `type`, `name`, `filters`, `order`, `sort`, `groupBy`, `limit`, `summaries` | כן |
| סוגי תצוגה `table`, `cards` ‏(`image:`), `list`, `kanban` (לפי `groupBy`), `map` ‏(`coordinates:`) | כן |
| סוגי תצוגה של תוספים | מוצגים כטבלה |
| סיכומים מובנים: Average, Min, Max, Sum, Range, Median, Stddev, Earliest, Latest, Checked, Unchecked, Empty, Filled, Unique | כן |
| `this` — קובץ ה-`.base` כשהוא פתוח, הפתק המטמיע כשהוא מוטמע | כן |

ביטויים כתובים בשפת Bases: ‏`note.x` (או סתם `x`), `file.x`, `formula.x`,
`this.file.x`; אופרטורים `+ - * / %`, ‏`== != < <= > >=`, ‏`! && ||`; טקסט,
מספרים, רשימות `[a, b]`, ביטויים רגולריים `/a.c/i`; חשבון תאריכים עם משכי
זמן (`today() - "1w"`, ‏`date(note.due) + "1M"`).

**פונקציות:** 66 מתוך 68 הפונקציות בתיעוד של Bases רצות (97%): כל
הפונקציות הגלובליות חוץ מ-`icon()`, וכל המתודות על ערך כלשהו, טקסט, מספרים,
תאריכים, רשימות (כולל `map`, ‏`filter`, ‏`reduce` עם `value`, ‏`index`,
‏`acc`), קישורים, קבצים, אובייקטים וביטויים רגולריים.

לא נתמכות — עם הודעה ברורה במקום ערך שגוי:

- `icon()` — ההודעה: "Bases function icon() is not supported here yet".
  ערכת האייקונים של Obsidian גדולה מכדי לטעון אותה בפתק.
- `html()` — מוצג כטקסט רגיל, אף פעם לא כ-markup (נספר כלא נתמך).

## הבדלים שכדאי לדעת

- **תאריכים ב-UTC.** ‏`today()` הוא התאריך ב-UTC, כמו בנוסחאות מסד הנתונים,
  כך ש-base נותן אותה תשובה בכל מחשב.
- **`file.name` כולל את הסיומת** (`Dune.md`), כמו ב-Obsidian;
  ‏`file.basename` הוא `Dune`.
- **`file.ctime`** הוא זמן השינוי: אחסון הקבצים של הדפדפן לא שומר זמן יצירה.
- **סדר טקסט** טבעי (`2` לפני `10`), לטינית לפני עברית.

## מיון ושמירה

לחיצה על כותרת עמודה ממיינת (לחיצה נוספת הופכת). ב-base מוטמע,
**שמירת המיון הזה ב-…** כותבת את ה-`sort:` החדש לתצוגה הזאת בקובץ ה-`.base`
— ההערות, סדר המפתחות וכל השאר בקובץ נשארים כמו שהיו. פתיחה ושמירה של base
בלי עריכה שומרות על אותם נתוני YAML.

## סט הזהב

בתיקייה `src/__tests__/fixtures/bases/` יש 20 קובצי `.base` והכספת שהם רצים
עליה (`vault.ts`). הקובץ `expected.json` מפרט לכל קובץ את השורות, את הסדר
שלהן וכמה ערכים — שחושבו ביד לפי הכללים של Bases. הבדיקה
`basesGolden.test.ts` בודקת את כל ה-20, ושכל קובץ שנקרא ונכתב בחזרה בלי
עריכה מכיל את אותו YAML.

לאימות מול Obsidian 1.14: יוצרים את הפתקים של `vault.ts` בכספת ריקה, מעתיקים
אליה את 20 קובצי ה-`.base`, פותחים כל אחד ומשווים את התצוגה הראשונה שלו
ל-`expected.json`. כל הבדל הוא באג לדווח עליו.

## קשרים ו-rollups (של Lumen)

שני מפתחות ברמה העליונה מוסיפים קשרים ו-rollups כמו ב-Notion. זו הרחבה של
Lumen: הקובץ נשאר YAML תקין, אבל Obsidian לא קורא את המפתחות האלה, ולכן
העמודות שלהם ריקות שם.

```yaml
relations:
  tasks:                 # הפתקים שהמאפיין project שלהם מקשר לכאן
    property: project
    incoming: true
  team: members          # הפתקים שהקישורים ב-members של הפתק הזה מצביעים עליהם
rollups:
  hours:    { relation: tasks, property: estimate, function: sum }
  open:     { relation: tasks, function: count }
  next_due: { relation: tasks, property: due, function: earliest }
  cost:     { relation: team, property: rate, function: sum }
views:
  - type: table
    name: פרויקטים
    order: [file.name, relation.tasks, rollup.hours, rollup.next_due]
```

- **קשר** הולך אחרי מאפיין קישור: `[[קישור]]` אחד או רשימה, כמו ש-Obsidian
  כותב אותם (כינויים ונתיבים נפתרים כמו בכל קישור). כברירת מחדל הוא יוצא:
  הפתקים שהמאפיין מצביע עליהם. עם `incoming: true` הכיוון הפוך: הפתקים
  שהמאפיין שלהם מצביע על הפתק הזה. כך מקבלים את שני הצדדים של קישור בלי
  לכתוב אותו פעמיים.
- **rollup** מחשב `count`,‏ `sum`,‏ `avg`,‏ `min`,‏ `max`,‏ `earliest` או
  `latest` על מאפיין של הפתקים הקשורים. זה יכול להיות `note.x`,‏ `file.x`,
  נוסחה של ה-base (`formula.x`, שמחושבת לכל פתק קשור) או rollup אחר.
- בתצוגה, העמודות הן `relation.<שם>` ו-`rollup.<שם>`. הכותרות שלהן הן
  השמות, אלא אם `properties:` נותן להן `displayName`.

## תצוגות לוח שנה וציר זמן (של Lumen)

```yaml
views:
  - type: calendar
    name: מועדים
    date: due            # ברירת מחדל: date
  - type: timeline
    name: שלבים
    date: start
    end: finish          # לא חובה: בלעדיו פריט הוא יום אחד
```

- **לוח שנה** מציג חודש, וכל פתק ביום של התאריך שלו. **ציר זמן** מציג לכל
  פתק פס מתאריך ההתחלה עד תאריך הסיום.
- כדי להעביר פתק ליום אחר, גררו אותו, או התמקדו בו ולחצו **Alt + ←/→** ליום,
  **Alt + ↑/↓** לשבוע (החיצים הולכים לפי כיוון הטקסט, כך שבעברית → זז
  אחורה). בקובץ של הפתק משתנה רק מאפיין התאריך הזה, וכל שאר הבתים נשארים
  כמו שהם. פס בציר הזמן שומר על האורך שלו, כך שגם הסוף שלו זז באותו מספר
  ימים.
- ב-Obsidian סוגי התצוגה האלה מוצגים כטבלה.

## מסדים גדולים ו-CSV

- טבלה של יותר מ-200 שורות מציירת רק את השורות שרואים, כך ש-10,000 שורות
  נגללות בחלקות. סינון ומיון של 10,000 פתקים לוקחים הרבה פחות מ-100ms.
- **ייצוא CSV** שומר את התצוגה הנוכחית: העמודות והשורות שלה, ב-UTF-8 עם
  BOM, כך ש-Excel פותח עברית נכון.
- **ייבוא CSV…** מוסיף פתק לכל שורה, בתיקייה שנקראת על שם ה-base:
  - העמודה הראשונה היא שם הפתק.
  - שאר העמודות הופכות למאפיינים: מספרים, `true` / `false` וטקסט, וכותרות
    בעברית נשמרות.
  - מאפיינים שהמסנן של ה-base קובע (כמו `type == "task"`) נוספים, כך
    שהפתקים החדשים מופיעים בתצוגה.
  - שם תפוס מקבל מספר.
