המודלים שרצים בדפדפן (הכתבה, Whisper, embeddings, דירוג מחדש, מודלי שיחה
של web-llm, תרגום, ניקוד) יורדים פעם אחת ונשמרים במכשיר. אף מודל לא תלוי
בשרת אחד. כל קובץ מנוסה מהמקורות האלה, לפי הסדר:

| # | מקור | מתי משתמשים בו |
|---|---|---|
| 1 | **Hugging Face**, ב-commit הנעוץ ב-`models/registry.json` | ראשון, כשהוא עונה. |
| 2 | **המראה של Lumen**: release אחד ב-GitHub לכל מודל, במאגר של הפרויקט | כש-Hugging Face חסום, לא זמין או מחזיר בייטים אחרים. |
| 3 | **העותק שלך**: כתובת אינטרנט שהזנת, או קבצים שבחרת במכשיר | כששני המקורות הקודמים לא עובדים, למשל ברשת סגורה. |

## כל קובץ נבדק

`models/registry.json` מפרט כל קובץ של מודל עם הגודל וה-**sha256** שלו.
קובץ משמש רק כשהוא תואם בדיוק, לא משנה איזה מקור הגיש אותו. מקור שמגיש
בייטים אחרים מדולג, והמקור הבא מנוסה. קובץ שאין לו sha256 מפורסם מגיע רק
מ-Hugging Face ב-commit נעוץ, אף פעם לא ממראה או מכתובת שהזנת.

קבצים שנבדקו נכנסים למטמון שהספרייה של המודל קוראת, כך שטעינת המודל אחר
כך לא שולחת שום בקשה.

## העותק שלך

**הגדרות AI ← מקורות להורדת מודלים**:

- **העותק שלך**: כתובת אינטרנט במבנה של ה-releases במראה,
  `<כתובת>/<תג release>/<קובץ>`. שם הקובץ הוא הנתיב שלו במאגר המודל, עם
  `__` במקום `/`. למשל: מורידים את הקבצים של release לתיקייה בשם התג שלו
  ומגישים אותה. מדיניות האבטחה של ההתקנה (CSP `connect-src`) צריכה להתיר
  את הכתובת.
- **הוספת קובצי מודל מהמכשיר הזה…**: בוחרים קבצים שכבר יש לך. Lumen שומר
  כל קובץ שהגודל וה-sha256 שלו תואמים לקובץ מודל ברשימה, בלי קשר לשם שלו.
  השאר מדווחים כקבצים שלא זוהו.

## המראה של Lumen

את העותק מחזיק GitHub Releases: כל קובץ יכול להגיע עד 2 GiB, ו-GitHub לא
מגביל את הגודל הכולל או את התעבורה של release. קישורי ההורדה של GitHub לא
שולחים כותרת CORS, ולכן דפדפן לא יכול לקרוא אותם ישירות. Cloudflare Worker
קטן (`edge-workers/model-mirror`, בתוכנית Workers החינמית) מוסיף את הכותרת
הזו בלבד ומעביר את הקובץ. הוא לא שומר כלום ויכול להגיע רק ל-releases מסוג
`models-*`. גם על התוכן אין צורך לסמוך עליו, כי האפליקציה בודקת את ה-sha256.

Cloudflare R2 נבדק ולא נבחר. השכבה החינמית שלו היא 10 GB-חודש של אחסון
עם תעבורה יוצאת חינם, וזה קטן מדי בשביל מודלי web-llm. בנוסף, הכתובות שלו
ב-`r2.dev` מוגבלות בקצב ומיועדות לפיתוח בלבד.

התקנה מפעילה את המראה עם `VITE_MODEL_MIRROR_URL`, והבנייה מוסיפה את
המקור שלו ל-CSP. עד אז, שלב 2 מדולג.

## למתחזקים

```sh
npm run models:mirror -- --check            # מה עוד לא יכול לרדת בלי Hugging Face (בלי רשת)
npm run models:mirror -- --pin              # נעיצת revisions ו-sha256 של כל קובץ (צריך Hugging Face)
npm run models:mirror -- --upload           # release לכל מודל, כל קובץ נבדק קודם
npm run models:mirror -- --verify --deep    # קריאת כל קובץ מהמראה בלבד ובדיקת sha256
```

כברירת מחדל משקפים רק מודלים שסיווג הרישיון שלהם הוא `allowed`. ההערות של
כל release כוללות את הרישיון והייחוס של המודל.
