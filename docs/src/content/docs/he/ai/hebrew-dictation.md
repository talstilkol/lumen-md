ההכתבה רצה במכשיר שלך. השמע לא יוצא ממנו.

## איזה מודל, מתי

| מצב | מודל | גודל | רישיון |
|---|---|---|---|
| הכתבה חיה, בזמן הדיבור | Zipformer2 של ivrit.ai, הזרמה (WASM) | 72 MB | CC BY 4.0 |
| כל משפט שהסתיים, ב-GPU עם WebGPU ו-f16 | Whisper large-v3-turbo של ivrit.ai | כ-563 MB | Apache-2.0 |
| כל משפט שהסתיים, בלי WebGPU או בטלפון | Ozen v1 (מזוקק מה-turbo של ivrit.ai) | כ-164 MB | Apache-2.0 |
| קובץ שמע או הקלטה בעברית | turbo ב-GPU חזק, אחרת Ozen v1 | | |

**הכתבה חיה מזרימה קודם, ואז מתקנת.** בזמן שמדברים, מודל ההזרמה מציג
טקסט מיד. כשעוצרים, השמע של המשפט עובר דרך Whisper, והתוצאה נכנסת
במקום הטקסט. זה קורה רק אם היא מגיעה תוך 2 שניות ונקראת כאותו משפט.
אחרת נשאר טקסט ההזרמה, כך שמעבר שני איטי או מבולבל לא מאבד את המילים
שלך.

**שום דבר לא יורד בזמן הכתבה.** המעבר השני משתמש במודל רק אם הוא כבר
במכשיר. כדי לקבל אותו, מתמללים קובץ עברי אחד: turbo ב-GPU מתאים, ו-Ozen
v1 בכל מקום אחר. בלי WebGPU, Ozen רץ על WebAssembly, וזה עובד גם
בטלפון.

למה Ozen v1 החליף את whisper-base לעברית: לפי כרטיס המודל שלו, ה-WER
שלו 8.6% לעומת 48% של whisper-base בסט הפודקאסטים של ivrit.ai
(eval-d1), בגודל דומה.

## איך מודדים דיוק

את ה-WER (שיעור שגיאות המילים) מודדים על **FLEURS-he validation**,
הסט שבו מודל ההזרמה מגיע ל-23.6%. היעד הוא **15% לכל היותר**.

```sh
npm run eval:asr-web -- --fleurs <התיקייה מ-scripts/asr/fleurs_spike.py>
```

המדידה מריצה את אותם קובצי ONNX ואותן הגדרות שהדפדפן משתמש בהם. זה גם
שלב אחד ב-`npm run models:day`.

הדוח מציג שתי צורות נרמול, זו לצד זו:

- **v1**: בלי ניקוד, בלי פיסוק, מקף מפריד מילים, אותיות קטנות.
- **v2**: v1, ובנוסף מספר נחשב זהה בין אם נכתב במילים ובין אם בספרות
  (״אלפיים ועשרים״ = ״2020״), ״%״ שווה למילה ״אחוז״, ואות שימוש אחת
  שצמודה למספר היא מילה נפרדת (״ב2020״ = ״ב 2020״). מילים לועזיות **לא**
  מתועתקות (״Google״ ≠ ״גוגל״), והשגיאה הזאת נשארת בציון.

v2 הוא המספר הראשי. v1 נשאר לצידו, כדי שאפשר יהיה להשוות לריצות
קודמות.
