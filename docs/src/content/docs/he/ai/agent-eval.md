הערכת הסוכנים מריצה מקרים קבועים דרך **זמן הריצה האמיתי של הסוכנים**:
אותם פרומפטים, כלים, מפענחים ובודקים שהעורך משתמש בהם. כל בדיקה
דטרמיניסטית, ולכן אפשר להשוות שני מודלים (או שתי גרסאות של פרומפט) על
אותם מספרים.

## מה נבדק

- **14 סוכנים, לפחות 5 מקרים לכל אחד**, ולכל סוכן לפחות קלט אחד בעברית
  ואחד באנגלית (71 מקרים בסך הכול): tagger, outliner, tasker, translator,
  proofreader, diagrammer, charter, committer, writer, linker, templater,
  stylist, researcher ו-builder-spec.
- **סוכן המחקר** מקבל רשת (חיפוש ודף מדומים), ציטוטים (הערות שוליים
  `[^1]` שנבדקות מול המקורות), את ספריית הגזירים, שאלה בעברית, ודף עם
  הוראה שתולה ("IGNORE PREVIOUS INSTRUCTIONS…") שאסור לתשובה לבצע.
- **התרשימים מקומפלים.** כל תשובה של ה-diagrammer עוברת במפענח Mermaid
  האמיתי (הבדיקה `mermaid`), ולא בתבנית טקסט.
- **התגיות באות מהכספת.** מקרי ה-tagger דורשים לפחות תגית אחת שכבר קיימת
  בכספת ההערכה (הבדיקה `someOf` על התוצאה של `list_tags`).
- **בכל מקרה צפויה קריאה לכלי** (למשל `list_tags`, `validate_mermaid`,
  `git_diff`, `fetch_page`), שזמן הריצה מבצע.

המקרים נמצאים ב-`src/agents/eval/fixtures.ts` וב-`src/agents/eval/moreCases.ts`.

## הרצה

```bash
ollama pull qwen2.5:7b
npm run eval:agents -- --model qwen2.5:7b
npm run eval:agents -- --model llama3.1:8b --only tagger,researcher-he-web
```

ההרצה כותבת שלושה קבצים ל-`eval/results/` (אפשר לשנות עם `--out`):

| קובץ | מה יש בו |
|---|---|
| `agents-<date>-<model>.md` | טבלה אחת: מקרה, סוכן, תוצאה, ניסיונות, זמן, בדיקות שנכשלו |
| `agents-<date>-<model>.json` | אותן תוצאות, בשביל `npm run eval:compare` |
| `agents-<date>-<model>.html` | עמוד עצמאי, בלי סקריפטים ובלי רשת: מספר ההצלחות לכל סוכן, ואחר כך כל המקרים |

פתחו את קובץ ה-HTML בדפדפן. סוכן שמסומן **FAIL** הוא סוכן שבאחד המקרים
שלו ההרצה נכשלה או שלא כל הבדיקות עברו. עמודת ההערות אומרת מה בדיוק.

## השוואה בין הרצות

`npm run eval:compare -- eval/results/agents-<date>-<model>.json` משווה
הרצה לבסיס השמור של אותו מודל. מקרה שעבר קודם ונכשל עכשיו הוא רגרסיה, וכך
גם מקרה שנעלם. בשני המקרים קוד היציאה הוא 1.

## ב-CI

אותם מקרים רצים מול שרת Ollama מדומה (`npm run fake-ollama`) ב-HTTP
אמיתי. השרת המדומה עונה בתשובת הייחוס של כל מקרה, ולכן ה-CI בודק את זמן
הריצה ואת המקרים עצמם, לא את איכות המודל. איכות המודל נמדדת רק בהרצה חיה
על מכונה עם Ollama.
