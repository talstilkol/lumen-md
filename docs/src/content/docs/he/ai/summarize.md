`⌘K → "AI: Summarize This Note (on this device)"` והכפתור **סיכום** בחלונית
[שאלו את ה-PDF](/he/workspace/pdf-chat/) יוצרים סיכום קצר שבו **כל משפט מועתק
מהטקסט** — מקוצר ב-"…" במקום שבו הושמטו מילים — ונבדק מולו מילה במילה
(`quoteContained`, הכלל של ציטוטי המחקר). משפט שאינו בטקסט לעולם לא מוצג.
ב-PDF כל משפט מקושר לעמוד ולשורה שלו.

## השכבות

| שכבה | מתי | מה |
|---|---|---|
| ‏Summarizer API של Chrome | טקסט באנגלית, והמודל כבר נמצא בדפדפן | הסיכום שבמכשיר של Chrome — משמש רק אם לפחות 95% מהמשפטים שלו נמצאים בטקסט (הוא מנסח מחדש לעתים קרובות) |
| מודל מקומי | אחרת | הסוכן `summarizer` ב-Ollama או במודל שבדפדפן — **רק מבצעים מקומיים**, בכל מדיניות AI. לעברית: DictaLM 3.0 1.7B ב-Ollama כשהוא מותקן; אחרת הבחירה המקומית של זמן הריצה (Qwen3 ב-web-llm בדפדפן). טקסט ארוך מסוכם קטע אחרי קטע, ואז עוד פעם על סיכומי הקטעים. |
| חילוצי | אין מודל מקומי, או שאין תוצאה שמישה | המשפטים שנושאים את מילות התוכן השכיחות ביותר בטקסט, לפי הסדר — בלי מודל בכלל |

ה-Summarizer של Chrome אינו תומך בעברית, ולכן טקסט בעברית תמיד עובר למודל
המקומי. מודל שבתשובה שלו פחות מ-80% מהמשפטים נמצאים בטקסט מתבקש לנסות שוב
פעם אחת, עם הסיבה.

מתקינים את המודל העברי ב-Ollama (בספרייה שלו הוא מופיע כ-DictaLM 3.0), ו-Lumen
בוחר בו לסיכומים בעברית לפי שמו.

## מדידה

`npm run eval:summarize` מסכם את המסמכים של סט הזהב לסיכומים (תוכנית 7.10,
`eval/golden/summarize`) ב-Ollama שלכם ומדווח על שיעור משפטי המודל שעוברים את
בדיקת העיגון **לפני** שמושמט משהו (יעד: ≥ 95%), עם כיסוי מילות מפתח כאות נוסף.
‏`LUMEN_EVAL_SUMMARY_DIRS` מוסיף את חלק המבחן המוחזק שנבנה עם זרע הזהב, לכל 20
המסמכים.
