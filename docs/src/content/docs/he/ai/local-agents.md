פקודות ה-AI של Lumen הן **סוכנים**: הגדרה של מה לשאול את המודל, אילו כלים
מותר לו לקרוא, איזו צורה התשובה צריכה לקבל ואיך לבדוק אותה. זמן ריצה אחד
(`src/agents/runtime.ts`) מריץ כל הגדרה מול ה**מבצע** הזמין הראשון, במכשיר
הזה בכל פעם שאפשר:

| מבצע | איפה הוא רץ | קריאה לכלים | פלט JSON |
|---|---|---|---|
| Ollama | שרת Ollama מקומי | מובנית (`tools`) | מובנה (`format`) |
| web-llm | הדפדפן שלכם, על ה-GPU | פרוטוקול JSON-ReAct | מצב JSON |
| `chat()` | הספק שבחרתם, יהיה אשר יהיה | פרוטוקול JSON-ReAct | הנחיה |

**מדיניות ה-AI** (`⌘K → "AI: Local or Cloud Policy"`) קובעת אם אי פעם מותר
לפנות לספק ענן. ברירת המחדל בהתקנה חדשה היא *מקומי בלבד*.

## מה ריצה עושה

1. בוחרת את המבצע הזמין הראשון לפי סדר ההעדפה של הסוכן.
2. שולחת את הנחיות המערכת והמשתמש. כשלסוכן יש כלים והמבצע לא יודע לקרוא להם
   באופן מובנה, ההנחיה מלמדת את פרוטוקול JSON-ReAct: המודל עונה
   `{"tool": …, "args": …}` או `{"final": …}`, אובייקט JSON אחד בכל תור.
3. מבצעת כל קריאה לכלי. כלים שכותבים או פונים לרשת צריכים הרשאה שהפקודה
   נותנת במפורש; מודל לעולם לא יכול לכתוב במקום שלא ציפיתם.
4. מפענחת את התשובה הסופית (JSON כשהסוכן מצהיר על סכמה) ומריצה את
   ה**מאמתים** של הסוכן — תרשים Mermaid חייב להתקמפל, אפשרות ECharts צריכה
   סדרות וצירים, תגיות חייבות להיות קיימות, היסטים חייבים ליפול בתוך הטקסט.
5. כשאין תשובה שמישה, **סוכן השיפור** (המבקר) מאבחן את הכישלון ומציע שינוי
   אחד לניסיון חוזר — טמפרטורה 0 עם שגיאת המאמת שמוזנת בחזרה, ואחר כך דרג
   מודל גדול יותר — עד שני ניסיונות חוזרים. אם גם זה נכשל, הריצה מסתיימת עם
   **הצעות** שאפשר לפעול לפיהן: להפעיל Ollama, להתיר את המקור של האפליקציה
   (`OLLAMA_ORIGINS`), למשוך מודל, לפצל את המסמך, לנסות מבצע אחר, או להתיר
   את הענן.
6. כשהניסיונות החוזרים נגמרו, מודל מקומי קטן (הדרג הזעיר) קורא את הכישלון
   ויכול להוסיף הצעה או שתיים בשפה פשוטה. לוח ההצעות נפתח מעצמו; לחיצה על
   הצעה מבצעת אותה (מושכת את המודל, מחליפה מבצע, משנה את המדיניות) ומריצה את
   הפקודה שוב.

כל ריצה נרשמת במכשיר: `⌘K → "AI: Recent Agent Runs"` מציג את המבצע, המודל,
הקריאות לכלים, הניסיונות החוזרים והכישלונות של 50 הריצות האחרונות.

## הגדרות ה-AI

`⌘K → "AI: Settings (local agents)"` מרכז הכול בלוח אחד:

- מדיניות ה-AI;
- **מי מריץ את הסוכנים** — אוטומטי (Ollama ← דפדפן ← ספק שיחה) או מבצע אחד
  קודם, עם בדיקה חיה של *זמין / לא זמין* לכל אחד;
- הכתובת והמודל של Ollama, עם המודלים שכבר מותקנים;
- המודל שבדפדפן, כרטיס המכשיר (WebGPU,‏ f16, הערכה של תקציב VRAM) והקטלוג,
  כשמודלים גדולים מדי למכשיר הזה מושבתים;
- הכתובות של הדקדוק (LanguageTool) ושל המחקר (worker של SearXNG);
- פרופיל סגנון הכתיבה שלכם, פעיל / כבוי;
- עשר ריצות הסוכנים האחרונות.

הלוח כותב את אותן הגדרות שזמן הריצה קורא; שום דבר לא נשמר פעמיים. תקציב
ה-VRAM הוא הערכה מהרמזים הגסים של הדפדפן, לא מדידה.

## תמלול ו-embeddings במכשיר

זיהוי דיבור ו-embeddings של טקסט לא עוברים דרך מודל שיחה: הם רצים ב-worker
שני על [transformers.js](https://github.com/huggingface/transformers.js) עם
ONNX Runtime ‏(WebGPU כשה-GPU שמיש, wasm אחרת). קובצי ONNX Runtime מוגשים
מהמקור של האפליקציה עצמה (`/ort/`), כך ששום CDN לא נקרא; המודלים מגיעים
מ-Hugging Face ונשמרים במטמון של הדפדפן.

| משימה | מודל | גודל | הערות |
|---|---|---|---|
| תזכיר קולי (`🎙 Voice memo`) | `onnx-community/whisper-small` | כ-250 MB | ‏WebGPU; רב-לשוני (כולל עברית) |
| תזכיר קולי ב-GPU חזק | `onnx-community/whisper-large-v3-turbo` | כ-800 MB | ‏WebGPU, תקציב של 6 GB לפחות |
| תזכיר קולי בלי WebGPU | `onnx-community/whisper-tiny` | כ-40 MB | ‏wasm, איטי יותר |
| embeddings לחיפוש החכם | `Xenova/multilingual-e5-small` | כ-120 MB | ‏384 ממדים, כ-100 שפות |

תחת *מקומי בלבד* ה-API של Whisper בענן לעולם לא משמש; תחת *מקומי קודם* הוא
החלופה כשהמסלול המקומי נכשל; תחת *ענן* הוא משמש ישירות.

## Ollama מהאפליקציה המתארחת

דף שמוגש מ-`https://lumen-md.vercel.app` יכול לקרוא ל-Ollama המקומי שלכם רק
כש-Ollama מתיר את המקור הזה:

```
OLLAMA_ORIGINS=https://lumen-md.vercel.app ollama serve
```

(ב-macOS:‏ `launchctl setenv OLLAMA_ORIGINS https://lumen-md.vercel.app`
ומפעילים מחדש את Ollama). בלי זה Ollama עונה `403`, וסוכן השיפור מציע בדיוק
את התיקון הזה. אפליקציית שולחן העבודה ובניות פיתוח ב-`localhost` לא צריכות
שינוי.

## מחקר, דקדוק וחיפוש במכשיר הזה

`docker/local-ai.yml` מפעיל שלושה שירותים:

| שירות | פורט | מה הוא עושה |
|---|---|---|
| SearXNG | 8888 | מטא-חיפוש, בלי מפתח API |
| שירות המחקר | 8787 | אותו worker ש-Lumen פורסת (`edge-workers/research`), מורץ עם `wrangler dev`: חילוץ דפים ועוד חיפוש SearXNG |
| LanguageTool | 8010 | בדיקות דקדוק ואיות |

```
docker compose -f docker/local-ai.yml up -d
```

ואז `⌘K → Research: Settings → SearXNG on this machine` ומקלידים
`http://localhost:8787`. שאלות מחקר מתוכננות ונענות על ידי המודל המקומי
שלכם; הציטוטים עדיין מאומתים מילה במילה מול הדפים. תחת *מקומי בלבד* שירות
מחקר מחוץ למכשיר או לרשת הזו נדחה. בהתקנה חדשה עם המדיניות *מקומי בלבד*,
SearXNG הוא ספק המחקר ברירת המחדל.

## הערכת מודל מקומי

`npm run eval:agents` מריץ שנים-עשר מקרים קבועים — רובם בעברית — דרך זמן
הריצה האמיתי של הסוכנים מול ה-Ollama שלכם, וכותב דוח ל-`eval/results/`:

```bash
ollama pull qwen2.5:7b
npm run eval:agents -- --model qwen2.5:7b
npm run eval:agents -- --model llama3.1:8b --only tagger-he,tasker-he
```

ב-CI אותם מקרים רצים מול **שרת Ollama מזויף** (`npm run fake-ollama`,
`scripts/fake-ollama.mjs`) מעל HTTP אמיתי: זמן הריצה, מבצע ה-Ollama,
המפענחים והמאמתים נבדקים בכל PR בלי GPU. רק איכות המודל צריכה את הריצה
החיה.

כל בדיקה דטרמיניסטית (חלק העברית מתוך האותיות, מילים נדרשות ואסורות, אורכי
רשימות, מגבלות אורך, תבנית), כך שאפשר להשוות שני מודלים או שתי גרסאות הנחיה
על אותם מספרים. הדוח מציג כל מקרה עם עבר/נכשל, ניסיונות (ניסיונות חוזרים
שסוכן השיפור ביקש) וזמן. תשובות הייחוס ב-`src/agents/eval/fixtures.ts` רצות
ב-CI דרך המפענח והמאמתים של כל סוכן, כך שתשובת ייחוס שבורה נתפסת לפני ריצת
GPU ארוכה.
