כל פקודת AI ב-Lumen היא **סוכן**: הגדרה שקובעת מה שואלים את המודל, באילו
כלים מותר לו להשתמש, באיזו צורה התשובה צריכה להגיע ואיך בודקים אותה. זמן
ריצה אחד (`src/agents/runtime.ts`) מריץ את כל ההגדרות על **המנוע** הראשון
שזמין, ובמכשיר שלכם בכל פעם שאפשר:

| מנוע | איפה הוא רץ | קריאה לכלים | פלט JSON |
|---|---|---|---|
| Ollama | שרת Ollama מקומי | מובנית (`tools`) | מובנה (`format`) |
| web-llm | בדפדפן, על ה-GPU | פרוטוקול JSON-ReAct | מצב JSON |
| `chat()` | הספק שבחרתם | פרוטוקול JSON-ReAct | דרך ההנחיה |

**מדיניות ה-AI** (בלוח הפקודות, ⌘K: **AI: מדיניות מקומי או ענן**) קובעת אם
מותר אי פעם לפנות לספק ענן. בהתקנה חדשה ברירת המחדל היא **מקומי בלבד —
שום דבר לא יוצא מהמכשיר**.

## מה קורה בריצה

1. זמן הריצה בוחר את המנוע הזמין הראשון, לפי סדר העדיפויות של הסוכן.
2. הוא שולח את הנחיית המערכת ואת הנחיית המשתמש. כשלסוכן יש כלים והמנוע לא
   יודע לקרוא להם בעצמו, ההנחיה מלמדת את המודל את פרוטוקול JSON-ReAct: בכל
   תור המודל עונה באובייקט JSON אחד, `{"tool": …, "args": …}` או
   `{"final": …}`.
3. הוא מבצע כל קריאה לכלי. קודם הארגומנטים נבדקים מול ה-JSON Schema של
   הכלי. כלים שכותבים או פונים לרשת צריכים הרשאה שהפקודה נותנת במפורש, וגם
   אז כלי כתיבה רק **מציע** שינוי שאתם מאשרים, וכלי רשת יוצא לרשת רק כשמדיניות
   ה-AI או ההסכמה שלכם מאפשרות זאת (ראו [כלים](#כלים)).
4. הוא מפענח את התשובה הסופית (JSON, כשהסוכן מגדיר סכמה) ומריץ את
   **הבודקים** של הסוכן: תרשים Mermaid חייב לעבור הידור, להגדרת ECharts
   צריכות להיות סדרות וצירים, התגיות חייבות להיות קיימות, וההיסטים חייבים
   ליפול בתוך הטקסט.
5. כשאין תשובה שאפשר להשתמש בה, **סוכן השיפור** (המבקר) מאבחן את הכשל ומציע
   שינוי אחד לניסיון חוזר: קודם טמפרטורה 0 יחד עם השגיאה של הבודק, ואחר כך
   דרגת מודל גדולה יותר, עד שני ניסיונות חוזרים. אם גם זה לא עוזר, הריצה
   מסתיימת ב**הצעות** שאפשר לפעול לפיהן: להפעיל את Ollama, לאשר את כתובת
   האפליקציה ב-Ollama (`OLLAMA_ORIGINS`), להוריד מודל, לפצל את המסמך, לנסות
   מנוע אחר או לאפשר ענן.
6. כשהניסיונות החוזרים נגמרים, מודל מקומי קטן (דרגת tiny) קורא את הכשל. הוא
   יכול להוסיף הצעה או שתיים בשפה פשוטה, וכשניסיון נוסף יכול לתקן את התשובה
   (פורמט, שפה או אורך לא נכונים), הוא מנסח הוראה אחת. זמן הריצה מבצע אז
   **ניסיון אחד נוסף** עם ההוראה הזאת.
7. לוח ההצעות (**ה-AI לא הצליח לענות — זה מה שעשוי לעזור**) נפתח מעצמו. זה
   קורה בכל פקודת AI, כולל מחקר, עבודות אצווה, חיפוש בכספת, בלוקי גרפים ועורך
   ה-WYSIWYG. לחיצה על הצעה מבצעת אותה ואז מריצה את הפקודה שוב:

| הצעה | מה הלחיצה עושה |
|---|---|
| **להפעיל את Ollama במחשב הזה** | בודקת כל שתי שניות אם Ollama עונה. כשהוא עונה, הפקודה רצה שוב; אחרי שתי דקות הבדיקה מוותרת, וסגירת הלוח עוצרת אותה. |
| **לפצל את המסמך ולהריץ על כל חלק** | מריצה את הסוכן על חלקים של כ-4000 תווים ומאחדת את התשובות. ההצעה מופיעה רק בסוכנים שהתשובה שלהם על חלק שקולה לתשובה על המסמך כולו: תגיות, משימות, תרגום, הגהה, קישורים. |
| **לבחור חלק קטן יותר ולהריץ שוב** | מופיעה בסוכנים שאי אפשר לפצל את התשובה שלהם, כמו תרשים או ראשי פרקים. סמנו את החלק הרצוי והריצו את הפקודה שוב. |
| **להוריד את המודל** … | מושכת את המודל ל-Ollama, או טוענת אותו בדפדפן. |
| **לנסות שוב עם** … | מריצה את הפקודה שוב עם מנוע אחר או עם דרגת מודל גדולה יותר. |
| **לאפשר ענן כגיבוי** | מעבירה את מדיניות ה-AI ל**מקומי קודם**. |
| **להוסיף מפתח** … | פותחת את **AI: החלף ספק**. |

### "לא טוב"

אחרי פקודה שמכניסה תשובה אחת לפתק (משימות, תרגום, תרשים, גרף, תגיות,
קישורים, ראשי פרקים, דקדוק, מחקר, פרופיל סגנון, הודעת commit), מופיע לכמה
שניות כפתור קטן: **לא טוב — לנסות שוב**. לחיצה עליו מריצה את הפקודה שוב על
אותו קלט, בטמפרטורה גבוהה יותר ובדרגת מודל אחת מעל, והמודל יודע איזו תשובה
נדחתה. ביומן הסוכנים, הריצה החדשה מקושרת לריצה שהיא מחליפה (`retryOf`).

כל ריצה נשמרת במכשיר. הפקודה **AI: ריצות סוכנים אחרונות** (⌘K) מציגה את
המנוע, המודל, הקריאות לכלים, הניסיונות החוזרים והכשלים של 50 הריצות
האחרונות.

## כלים

כל כלי מגדיר JSON Schema לארגומנטים שלו ותחום הרשאה. זמן הריצה דוחה קריאה
שהארגומנטים שלה לא תואמים לסכמה (מספרים וערכים בוליאניים שנשלחו כמחרוזות
מתקבלים), וכל קריאה, יחד עם התוצאה שלה, נרשמת ביומן של הריצה.

| תחום | כלים | מה זמן הריצה עושה |
|---|---|---|
| קריאה | `read_file`, `list_files`, `file_exists`, `search_workspace`, `get_frontmatter`, `list_tags`, `get_document`, `get_selection`, `get_headings`, `validate_mermaid`, `validate_echarts`, `validate_json`, `git_diff`, `extract_quotes`, `csv_parse`, `run_python` | תמיד מותר. |
| כתיבה | `write_file`, `set_frontmatter`, `replace_range` | צריך את הרשאת ה-`write` של הריצה. הכלי עצמו לא כותב כלום: הוא **מעמיד** את השינוי לאישור (`src/agents/staging.ts`), והריצה מחזירה את המזהים של מה שהועמד. רק אישור כותב את השינוי, ורק אם הקובץ או הטקסט שממנו הוא חושב לא השתנו בינתיים; אחרת הוא מסומן כהתנגשות. ריצה שבוטלה מושכת בחזרה את מה שהעמידה. |
| רשת | `search_web`, `fetch_page` | צריך את הרשאת ה-`network` של הריצה. שני הכלים עוברים דרך שירות המחקר (SearXNG מקומי או ה-worker של המחקר), אף פעם לא בבקשה ישירה לדף אינטרנט, ושולחים רק את השאילתה או את כתובת הדף. את השאילתה הסוכן מנסח בעצמו, ולפעמים מתוך הפתקים שלכם, כך שטקסט מהם יכול להופיע בה. במצב **מקומי בלבד** כל קריאה שואלת אתכם קודם: הבקשה לאישור מציינת את הכלי ואת השרת, ומציגה בדיוק את כל מה שיישלח. אחרי האישור הקריאה יוצאת בדיוק לשירות ועם ההגדרות שהוצגו. הסכמה חד-פעמית שנתתם למחקר ברשת לא חלה על סוכנים. בלי "כן" מפורש הקריאה נדחית לפני שמשהו נשלח, והדחייה נרשמת. כל בקשה נרשמת ביומן הפרטיות, עם סימון כשהיא יצאה בעקבות הסכמה. |

`git_diff` מציג את ה-diff המאוחד של ריפו משוכפל: ברירת המחדל היא HEAD מול
עותק העבודה (מה שה-commit הבא יתעד), ועם `staged` — מול ה-index.
`set_frontmatter` עורך frontmatter של YAML דרך מודל המסמך של `yaml`, כך
שההערות ושאר המפתחות נשארים כמו שהיו. `extract_quotes` משווה ציטוטים מילה
במילה לדף שנקרא באותה ריצה, לקובץ בכספת או למסמך הפתוח, ומחזיר את הטקסט
המדויק עם ההיסטים שלו. כל הכלים נעצרים כשהריצה מבוטלת.

## סקירת שינויים שסוכנים הציעו

כשסוכן מציע שינויים, הודעה קופצת מודיעה על כך, ובשורת המצב מופיע
מונה כמו **3 לאישור**. אותו לוח, **שינויים שסוכנים הציעו**,
נפתח גם מהפקודה **AI: סקירת שינויים שסוכנים הציעו** (⌘K). כל שינוי מוצג
כ-diff: קובץ שלם שורה אחר שורה, וקטע מהמסמך הפתוח מילה אחר מילה, מסומן כמו
שינוי במעקב, יחד עם הסוכן והריצה שהציעו אותו. אפשר **אישור** או **דחייה**
לכל שינוי בנפרד, או **לאשר הכול** / **לדחות הכול** בבת אחת. שום דבר לא
נכתב לפני שאתם מאשרים.

- שינוי במסמך פתוח (שמור או לא) נכנס לטקסט שלו בעורך, לא לקובץ שמתחתיו,
  והשמירה היא שכותבת אותו. בעורך המקור, ביטול (Undo) מחזיר אותו; בתצוגה
  המקדימה וב-WYSIWYG אי אפשר, והלוח אומר זאת. שינויים בקבצים אחרים נכתבים
  ישר לכספת.
- שינוי במסמך שלא נמצא בכספת (מסמך ללא שם או מסמך מיובא) נכנס תמיד רק
  למסמך שהסוכן עבד עליו, גם אם עברתם לשונית בינתיים. אם המסמך הזה נסגר,
  השינוי נדחה.
- כש**מצב הצעות** פעיל, שינוי שאישרתם נכנס כשינוי במעקב שמשויך לסוכן
  (`{~~old~>new~~}{>>@AI proofreader<<}`), כך שעדיין אפשר לקבל או לדחות אותו
  במקום.
- אם הטקסט שהשינוי מחליף נערך אחרי ההצעה, השינוי נדחה והלוח מסביר למה.
  כשהטקסט רק זז ממקומו ומופיע בדיוק פעם אחת, השינוי מוחל במקום החדש. אפשר
  לאשר כמה שינויים מאותה ריצה בכל סדר.
- ביטול ריצה מושך בחזרה את השינויים שהיא הציעה.

### איזה סוכן משתמש באילו כלים

| סוכן | כלים |
|---|---|
| tagger (תגיות) | `list_tags` |
| linker (קישורים) | `list_files`, `search_workspace` |
| outliner (ראשי פרקים) | `get_document`, `get_headings` |
| tasker, translator, proofreader (משימות, תרגום, הגהה) | `get_document` |
| diagrammer (תרשימים) | `validate_mermaid` |
| charter (גרפים) | `csv_parse`, `validate_echarts` |
| committer (הודעות commit) | `git_diff` (שורת נושא וגוף קצר) |
| writer, templater (כתיבה, תבניות) | `get_selection` |
| builder (בניית פרויקט) | `list_files` |
| stylist (סגנון) | `list_files`, `read_file` |
| researcher (מחקר) | `search_web`, `fetch_page`, `extract_quotes`, `search_workspace`, `read_file` |

את מה שסוכן צריך תמיד (התגיות של הכספת בשביל ה-tagger, רשימת הפתקים בשביל
ה-linker, הטבלה המפוענחת בשביל ה-charter, ה-diff בשביל ה-committer) זמן
הריצה מביא דרך אותו מסלול של כלים עוד לפני שהמודל מתחיל. כך המודל רואה את
זה כקריאה שהוא עצמו ביצע, ויכול לבקש עוד. גם הסיכום היומי קורא את הכספת
באותה דרך.

במודל קטן, כל תור מוגבל ל-JSON Schema (ה-`format` של Ollama, הדקדוק של
web-llm): קריאה לאחד הכלים של הסוכן עם ארגומנטים תקינים, או התשובה הסופית
בפורמט של הסוכן. סוכן שמזרים את התשובה (writer, templater) מקבל את תוצאות
הכלים שלו לפני שהוא מתחיל, והתשובה שלו עדיין מוזרמת.

ה-builder כותב את כל הפרויקט בבת אחת, רק כשכל הקבצים מוכנים: אם קובץ אחד
נכשל, שום קובץ לא נכתב.

### תוכן חיצוני (prompt injection)

דפי אינטרנט, תוצאות חיפוש, דפים שנשמרו מהרשת (התיקייה `Library` / `ספרייה`
או frontmatter עם `source: https://…`), פתקים שהגיעו משכפול או ממשיכה של
git, פתקים עם `untrusted: true` ב-frontmatter, והפתקים שהמחקר כותב (הם
נושאים את ה-frontmatter הזה, כי הם בנויים מדפים ומציטוטים) הם **תוכן
חיצוני**. מישהו אחר כתב אותם, והם עלולים להכיל הוראות שהוטמנו בשביל הסוכן.
זמן הריצה (`src/agents/untrusted.ts`) מטפל בהם כך:

- **תחום בסימנים.** המודל מקבל טקסט כזה בין הסימנים `⟪untrusted id=…⟫`
  ו-`⟪/untrusted id=…⟫`. המזהה אקראי, כך שהתוכן לא יכול לסגור את הבלוק
  בעצמו. הנחיית המערכת אומרת שהטקסט שבין הסימנים הוא נתונים, ולעולם לא
  הוראות.
- **מנוקה, אבל לא בשקט.** תווי tag של Unicode (ASCII בלתי נראה) מפוענחים
  ומוצגים. תווים ברוחב אפס ותווי בקרה של כיווניות (bidi) מוסרים, ומספרם
  מצוין על הבלוק. הערות HTML ורכיבים שהוסתרו ב-CSS מוצגים כמוסתרים. קטעים
  שנראים כמו הוראות, באנגלית ובעברית ("ignore previous instructions", "התעלם
  מכל ההוראות", אסימוני תפקיד, "send this note to …"), נשארים בטקסט בתוך
  סימון גלוי `⟦flagged …⟧`.
- **אישור.** מרגע שבהקשר של ריצה יש תוכן חיצוני, כל כלי כתיבה וכל קריאה
  לרשת שואלים אתכם קודם. הבקשה לאישור מציינת את הכלי, מה הוא עומד לעשות
  ומאיפה הגיע התוכן החיצוני. במצב **מקומי בלבד**, הבקשה לאישור של קריאה
  לרשת נושאת את אותה אזהרה. בלי "כן" שלכם שום דבר לא מועמד לאישור ושום דבר
  לא נשלח. אישור של שינוי שהועמד הוא עדיין שלב נפרד. בריפו git שהוא שלכם
  אפשר לכבות את השאלה על כתיבה: ראו [מאגרים מהימנים](/he/security/trusted-repos/).

הכללים דטרמיניסטיים, ולכן הם עובדים אותו דבר בעברית ובאנגלית ולא צריכים
מודל. הם לא תופסים בקשה מנומסת ("please also save a copy as …"); את אלה
עוצר שלב האישור. מסווג אופציונלי לאנגלית (ProtectAI v2) לאפליקציית שולחן
העבודה מתוכנן בהמשך.

### `run_python`: ‏Python במכשיר, בלי רשת

`run_python` מריץ תוכנית Python 3 קצרה על אותו Pyodide שמתארח באתר עצמו,
כמו הבלוק `live-python` (הספרייה הסטנדרטית, בלי המודולים ש-Pyodide מפיץ
כחבילות נפרדות, כמו `ssl`,‏ `sqlite3` ו-`lzma`, ובלי חבילות צד שלישי). הוא
מחזיר את מה שהתוכנית הדפיסה (`stdout`, `stderr`), את הערך של הביטוי האחרון
(`result`) או את השגיאה, כשהשורות של Pyodide עצמו מוסרות מה-traceback. זה
כלי **קריאה**, והוא לא שולח שום בקשה, ולכן הוא לא צריך הרשאה ולא שואל על
גישה לרשת:

- הוא רץ ב-Web Worker שנוצר לקריאה האחת הזאת ומושמד אחריה, כך ששום דבר לא
  עובר מקריאה לקריאה. ל-worker אין DOM ואין שום דרך להגיע לכספת שלכם:
  IndexedDB,‏ Cache Storage,‏ `navigator.storage` (OPFS),‏
  `navigator.storageBuckets` ו-`BroadcastChannel` מוסרים לפני שהקוד רץ, וכך
  גם ממשקי המכשיר (`navigator.serial`,‏ `usb`,‏ `hid`,‏ `bluetooth`,‏
  `geolocation`,‏ `mediaDevices`). אם הקוד צריך פתק, הסוכן מעביר את הטקסט
  ב-`inputs` (אובייקט JSON של עד 64 KB, שהקוד קורא כ-dict בשם `inputs`).
- אין רשת. אחרי ש-Pyodide טוען את הקבצים שלו (מהאתר הזה, תחת `/pyodide/`),
  ה-worker מחליף את `fetch`,‏ `XMLHttpRequest`,‏ `WebSocket`,‏
  `EventSource`,‏ `importScripts`, workers מקוננים ושאר הדרכים החוצה בגרסאות
  שתמיד נכשלות, גם על האובייקט הגלובלי של ה-worker וגם על ה-prototypes שלו.
  הוא גם מסרב להריץ JavaScript שנבנה ממחרוזות (`eval`, הבנאים של
  `Function`, ‏`setTimeout` עם מחרוזת). בצד של Python, audit hook חוסם
  sockets ובקשות `urllib`, ו-`pyodide.http` (`pyfetch`, `open_url`,
  `pyxhr`),‏ `pyodide.code.run_js`,‏ `micropip` ו-`pyodide_js.loadPackage`
  נכשלים. כל ניסיון נרשם ביומן הפרטיות כחסום, עם שם השרת בלבד (עד 20
  רשומות לקריאה).
- מגבלות: הקוד יכול לרוץ 10 שניות (`timeoutMs`, עד 30 שניות, נספרות מהרגע
  ש-Pyodide עלה). אחר כך ה-worker נעצר והתוצאה מסומנת `timedOut`. הפלט
  (stdout, ‏stderr והערך יחד) מוגבל ל-20,000 תווים, ואז מסומן `truncated`.
  גם הקוד עצמו מוגבל ל-20,000 תווים. ביטול הריצה עוצר את ה-worker.

הקריאה הראשונה טוענת את Pyodide (כ-10 MB, מהאתר הזה, כך שהוא עובד גם בלי
רשת אחרי שהאפליקציה נשמרה במטמון). כל קריאה מפעילה אותו מחדש.

### כל פקודת AI היא סוכן

כל פקודות ה-AI עוברות דרך זמן הריצה של הסוכנים: המנועים (מקומי קודם),
מדיניות ה-AI, המכסה, ההגנה מפני הזרקת הוראות והיומן. זה כולל גם את הפקודות
שפעם פנו למודל ישירות: טקסט הרפאים וההצעה בתוך השורה (`completer`), שכתוב
ב-AI (`rewriter`, שגם מכבד את פרופיל הסגנון שלכם), שאלה על הכספת
(`answerer`), הסיכום של תזכיר קולי (`memo-summarizer`), שלבי הארכיטקטורה,
הבדיקות וה-README של ה-builder, ועבודות אצווה (`batch`, על המודל המקומי של
העבודה, שמחויבות פעם אחת כשהעבודה נשלחת). בדיקה אוטומטית סורקת את הקוד:
שום דבר מחוץ למנועים לא פונה למודל ישירות.

## הגדרות AI

הפקודה **AI: הגדרות (סוכנים מקומיים)** (⌘K) מרכזת הכול בלוח אחד, **הגדרות
AI**:

- **מדיניות AI**;
- **מי מריץ את הסוכנים**: **אוטומטי (Ollama ← בדפדפן ← ספק הצ׳אט)**, או מנוע
  אחד שמקבל עדיפות, עם בדיקה חיה לכל אחד: **זמין** או **לא זמין**;
- הכתובת והמודל של Ollama, עם המודלים שכבר מותקנים;
- המודל שרץ בדפדפן, כרטיס המכשיר (WebGPU,‏ f16, הערכה של תקציב ה-VRAM)
  והקטלוג, כשמודלים גדולים מדי למכשיר הזה מושבתים;
- הכתובות של שירות הדקדוק (LanguageTool) ושל שירות המחקר (ה-worker של
  SearXNG);
- **סגנון הכתיבה שלי**, פעיל או כבוי;
- **הרצות סוכנים אחרונות**: עשר הריצות האחרונות.

הלוח כותב את אותן הגדרות שזמן הריצה קורא; שום דבר לא נשמר פעמיים. תקציב
ה-VRAM הוא הערכה לפי הרמזים הגסים שהדפדפן חושף, לא מדידה.

## מנהל המודלים

אותו לוח מנהל גם את המודלים עצמם:

- **מצב עלות AI**: **חסכוני**, **מאוזן** (ברירת המחדל) או **איכות**. במנועים
  המקומיים, המצב מזיז את דרגת המודל של הריצה הבאה: חסכוני מריץ מודל קטן
  בדרגה אחת ממה שהסוכן מבקש (tagger שמבקש מודל *small* יקבל *tiny*), איכות —
  גדול בדרגה אחת, ומאוזן — בדיוק מה שהוגדר. תקציב המכשיר עדיין חל, כך שמצב
  איכות במחשב עם 4 GB יקבל את המודל הגדול ביותר שנכנס, ולא מודל גדול יותר.
  ריצה שכבר התחילה ממשיכה עם המודל שלה; ניסיון חוזר שעולה דרגה עולה מהדרגה
  של המצב. ספק הצ׳אט בענן שומר על הניתוב שלו (ראו [עלות](/he/ai/cost/));
  המצב קובע גם כמה מהפתקים שלכם נשלח כהקשר.

  | דרגת הסוכן | חסכוני | מאוזן | איכות |
  |---|---|---|---|
  | tiny | tiny | tiny | small |
  | small | tiny | small | medium |
  | medium | small | medium | large |
  | large | medium | large | large |

  המצב מזיז רק את הבחירה *האוטומטית*. מודל שבחרתם בעצמכם גובר: מודל בדפדפן
  שבחרתם בלוח רץ בכל פעם שהוא לפחות בדרגה המבוקשת (בחרו **המומלץ למכשיר
  הזה** כדי לתת למצב לבחור), ומודל Ollama שהגדרתם רץ כשהוא מתאים לדרגה.

  הדרגות של Ollama נקבעות לפי מספר הפרמטרים, מבין המודלים שהתקנתם (tiny עד
  2.5B,‏ small עד 9B,‏ medium עד 16B, וכל מה שמעל הוא large); הדרגות של
  web-llm הן אלה שבקטלוג.
- **הורדת מודל ל-Ollama**: מקלידים שם (`qwen3:4b`,‏
  `hf.co/<owner>/<repo>`) ולוחצים **הורדה**. הלוח מזרים את `/api/pull` של
  Ollama ומציג את ההתקדמות על פני כל השכבות, בבייטים ובאחוזים, עם כפתור
  **ביטול**. כתובת שערכתם נשמרת קודם. מודל שמתפרסם ברישיון משלו (Llama,
  ‏Gemma, מודלים לשימוש לא מסחרי) מוצג בשמו בחלון **מודל ברישיון משלו**,
  ואתם מאשרים לפני ההורדה. בסיום רשימת המודלים המותקנים מתרעננת. ההורדה
  הולכת לשרת Ollama שבכתובת שמעל; שום תוכן מהפתקים לא מעורב בה.
- **אחסון מודלים**: כמה מהמכסה של הדפדפן האתר הזה תופס
  (`navigator.storage.estimate()`), ושני כפתורים. **ניקוי מודלים בדפדפן**
  פורק את המודל ומוחק את המטמונים של web-llm (`webllm/model`, `webllm/wasm`,
  `webllm/config`, ב-Cache Storage או ב-IndexedDB). **ניקוי מודלי דיבור
  וחיפוש** מוחק את המטמון של transformers.js ‏(Whisper, embeddings). המטמון
  של האפליקציה לעבודה בלי רשת והכספת שלכם לא נפגעים. בשימוש הבא המודל יורד
  שוב.
- **אין WebGPU**: ב-Firefox ל-Linux ול-Android עדיין אין WebGPU, ובדפדפני
  Android המצב משתנה. הלוח אומר את זה במפורש: מודל הצ׳אט בדפדפן כבוי שם,
  מודלי הדיבור והחיפוש רצים ב-WASM (לאט יותר, ובמודלים קטנים יותר),
  והסוכנים עוברים ל-Ollama (או לספק הצ׳אט, אם המדיניות מתירה).

## תמלול ו-embeddings במכשיר

זיהוי דיבור ו-embeddings של טקסט לא עוברים דרך מודל צ׳אט: הם רצים ב-worker
נפרד על [transformers.js](https://github.com/huggingface/transformers.js)
עם ONNX Runtime ‏(WebGPU כשאפשר להשתמש ב-GPU, ו-wasm אחרת). הקבצים של ONNX
Runtime מוגשים מהכתובת של האפליקציה עצמה (`/ort/`), כך שלא פונים לשום CDN;
המודלים מגיעים מ-Hugging Face ונשמרים במטמון של הדפדפן.

| משימה | מודל | גודל | הערות |
|---|---|---|---|
| תזכיר קולי (**🎙 תזכיר קולי (תמלול + סיכום)**) | `onnx-community/whisper-small` | כ-250 MB | WebGPU; רב-לשוני (כולל עברית) |
| תזכיר קולי על GPU חזק | `onnx-community/whisper-large-v3-turbo` | כ-800 MB | WebGPU, תקציב של 6 GB לפחות |
| תזכיר קולי בלי WebGPU | `onnx-community/whisper-tiny` | כ-40 MB | wasm, איטי יותר |
| embeddings לחיפוש החכם | `Xenova/multilingual-e5-small` | כ-120 MB | ‏384 ממדים, כ-100 שפות |

במצב **מקומי בלבד** לא משתמשים אף פעם ב-API של Whisper בענן; במצב **מקומי
קודם** הוא הגיבוי כשהמסלול המקומי נכשל; במצב **ענן** משתמשים בו ישירות.

## Ollama מהאפליקציה המתארחת

דף שמוגש מ-`https://lumen-md.vercel.app` יכול לפנות ל-Ollama המקומי שלכם רק
אם Ollama מאשר את הכתובת הזאת:

```
OLLAMA_ORIGINS=https://lumen-md.vercel.app ollama serve
```

(ב-macOS: ‏`launchctl setenv OLLAMA_ORIGINS https://lumen-md.vercel.app`
ואז מפעילים את Ollama מחדש). בלי זה Ollama עונה `403`, וסוכן השיפור מציע
בדיוק את התיקון הזה (**לאשר את האפליקציה ב-Ollama (OLLAMA_ORIGINS)**).
אפליקציית שולחן העבודה וגרסאות פיתוח על `localhost` לא צריכות שום שינוי.

## מחקר, דקדוק וחיפוש במחשב הזה

`docker/local-ai.yml` מפעיל שלושה שירותים:

| שירות | פורט | מה הוא עושה |
|---|---|---|
| SearXNG | 8888 | מנוע חיפוש-על, בלי מפתח API |
| שירות המחקר | 8787 | אותו worker ש-Lumen מפרסם (`edge-workers/research`), מורץ עם `wrangler dev`: חילוץ תוכן מדפים וחיפוש דרך SearXNG |
| LanguageTool | 8010 | בדיקת דקדוק ואיות |

```
export RESEARCH_TOKEN=$(openssl rand -hex 24)
echo "$RESEARCH_TOKEN"
docker compose -f docker/local-ai.yml up -d
```

שירות המחקר דורש אסימון משותף. העתיקו את הערך ש-`echo` הדפיס לשדה **אסימון
מחקר (RESEARCH_TOKEN)** בהגדרות ה-AI (ושמרו אותו: הרצות `docker compose`
בהמשך צריכות את אותו `RESEARCH_TOKEN`). אחר כך הריצו **🔎 מחקר: הגדרות…**
(⌘K), בחרו **SearXNG במחשב הזה (בלי מפתח; שירות מחקר מקומי)** והזינו
`http://localhost:8787`. את שאלות המחקר מתכנן ועונה עליהן המודל המקומי שלכם;
הציטוטים עדיין נבדקים מילה במילה מול הדפים. במצב **מקומי בלבד** שירות מחקר
שנמצא מחוץ למחשב או לרשת הזאת נדחה. בהתקנה חדשה עם מדיניות **מקומי בלבד**,
SearXNG הוא ספק המחקר שמוגדר כברירת מחדל.

## הערכת מודל מקומי

`npm run eval:agents` מריץ את מקרי הבדיקה הקבועים (לפחות חמישה לכל אחד
מ-14 הסוכנים, בעברית ובאנגלית) דרך זמן הריצה האמיתי של הסוכנים מול ה-Ollama
שלכם, וכותב דוח ב-Markdown, ‏JSON ו-HTML לתיקייה `eval/results/`. המקרים,
הבדיקות ואיך לקרוא את הדוח מוסברים ב[הערכת סוכנים](/he/ai/agent-eval/).

```bash
ollama pull qwen2.5:7b
npm run eval:agents -- --model qwen2.5:7b
npm run eval:agents -- --model llama3.1:8b --only tagger-he,tasker-he
```

ב-CI אותם מקרים רצים מול **שרת Ollama מדומה** (`npm run fake-ollama`,
‏`scripts/fake-ollama.mjs`) על HTTP אמיתי: זמן הריצה, המנוע של Ollama,
המפענחים והבודקים נבדקים בכל pull request, בלי GPU. רק איכות המודל דורשת
הרצה חיה.

כל בדיקה דטרמיניסטית (חלק האותיות העבריות, מילים שחייבות להופיע ומילים
אסורות, אורך רשימות, מגבלות אורך, תבנית), כך שאפשר להשוות שני מודלים או שתי
גרסאות של הנחיה על אותם מספרים. הדוח מפרט כל מקרה: עבר או נכשל, מספר
הניסיונות (הניסיונות החוזרים שסוכן השיפור ביקש) והזמן. תשובות הייחוס
ב-`src/agents/eval/fixtures.ts` רצות ב-CI דרך המפענח והבודקים של כל סוכן,
כך שתשובת ייחוס שבורה נתפסת עוד לפני הרצה ארוכה על GPU.

### מודל קטן אמיתי ב-CI

`npm run ci:real-model` מריץ כל סוכן פעם אחת מול מודל מקומי אמיתי,
`qwen3:0.6b` על Ollama ‏(Apache-2.0, כ-523 MB, תומך בקריאה לכלים). כל ריצה
היא בטמפרטורה 0, עם seed ‏42, בלי שלב חשיבה, ועם 64 טוקנים לכל היותר בכל
תור. הבדיקה שופטת את **הצורה** של כל תור, לא את הניסוח:
- קריאה לכלי מציינת אחד הכלים של הסוכן, והארגומנטים שלה עוברים את ה-JSON
  Schema של הכלי;
- תשובה סופית מתחילה בפורמט של הסוכן (JSON, כשלסוכן יש סכמה).

הסקריפט מוצא את Ollama, או מפעיל `ollama serve` אם הקובץ מותקן, ומוריד את
המודל אם הוא חסר. אם אחד מהם בלתי אפשרי (אין Ollama, אין גישה לרשת אל מאגר
המודלים), הוא כותב את `eval/results/real-skipped.md` עם הסיבה ויוצא עם קוד 0.
ה-workflow הלילי (`.github/workflows/real-model.yml`) שומר את המודל במטמון
ומגדיר `LUMEN_REAL_MODEL_REQUIRED=1`, כך ששם דילוג נחשב לכישלון. הוא בודק גם
את LanguageTool (באנגלית בלבד; אין לו עברית) ואת SearXNG כשירותים אמיתיים.
לתרחישים מרובי שלבים השתמשו ב-`--model qwen3:1.7b`.
