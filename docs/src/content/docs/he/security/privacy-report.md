"פרטי" זו טענה. ב-Lumen אפשר לבדוק אותה. יומן הפרטיות רושם כל בקשת רשת
שהתכונות של Lumen שולחות. אפשר לייצא אותו כ**דוח חתום**, לבדוק את הדוח
בסקריפט, ולהשוות אותו למה ש**מנתח רשת חיצוני** ראה באותה ריצה.

## ייצוא הדוח

⌘K ← *יומן פרטיות…* ← **ייצוא דוח חתום**. הקובץ מכסה את הסשן הזה, מרגע
שהלשונית נפתחה. לכל בקשה הוא אומר:

| | |
|---|---|
| מי | איזו תכונה (הקטגוריה והסיבה שלה: "Anthropic (Claude)", "הורדת מודל", …) |
| מתי | השעה |
| לאן | השרת |
| כמה | בתים שנשלחו והתקבלו, והאם הבקשה אושרה או נחסמה |

הסיכום (בקשות, כמה יצאו מהמכשיר ולאילו שרתים, בתים) מחושב מהרשומות האלה.
בקובץ אין אף פרומפט, פתק או כותרת.

הדוח נחתם בדפדפן ב-**Ed25519**, במפתח שנוצר במכשיר הזה בייצוא הראשון.
החצי הפרטי נשאר ב-IndexedDB ואי אפשר לייצא אותו. החתימה בפורמט של minisign,
כך שגם הסקריפט שלמטה וגם הכלי `minisign` יכולים לאמת אותה.

## בדיקת דוח

```sh
node scripts/privacy/verify-report.mjs lumen-privacy-report-….json
node scripts/privacy/verify-report.mjs report.json --local-only          # וגם: שום דבר לא יצא מהמכשיר
node scripts/privacy/verify-report.mjs report.json --pub device.pub      # נעיצת מפתח החתימה
node scripts/privacy/verify-report.mjs report.json --extract out/        # ואז: minisign -Vm out/report.json -p out/report.pub
```

הסקריפט בודק את החתימה ואת ההערה המהימנה (שנוקבת ב-SHA-256 של הדוח), ושהדוח
בצורה הקנונית שלו. הוא בודק את המבנה של כל רשומה: זמנים בתוך הסשן ולפי הסדר,
ו-`leftDevice` לפי הכלל של היומן. אחר כך הוא **מחשב את הסיכום מחדש** ודוחה
דוח שהסיכום שלו לא תואם לרשומות. בלי `--pub` הוא מוכיח שהקובץ לא השתנה מאז
שנחתם. עם `--pub` הוא מוכיח גם איזה מכשיר חתם עליו.

## מצב ביקורת

בדרך כלל היומן רושם תעבורת AI. ב**מצב ביקורת**
(`localStorage["lumen.privacy.audit"] = "1"`) הוא רושם גם כל בקשה אחרת שיוצאת
מהמכשיר ומהרשת המקומית, תחת *בקשה אחרת*. הבקשות האלה נרשמות אבל לא נחסמות
אף פעם. אז מריצים את האפליקציה דרך מנתח חיצוני:

```sh
node scripts/privacy/audit.mjs --sign ~/.lumen-release/lumen-release.key --publish
```

1. **mitmproxy** (`mitmdump`, גרסה 10.1 ומעלה) מקליט כל בקשה, כולל הבקשות
   של האפליקציה עצמה לשרת הפיתוח, וזה מוכיח שהוא היה בנתיב.
2. `e2e/privacy-audit.spec.ts` מריץ את המסע במדיניות **מקומי בלבד**, עם
   מפתחות ענן מוגדרים כדי לפתות כל נפילה לענן: התצוגות, ייצוא, פקודות ה-AI
   ובקשת ענן ידנית (שנחסמת). אחר כך הוא מייצא את הדוח החתום ושומר את יומן
   הבקשות של Playwright עצמו.
3. הסקריפט מאמת את הדוח ומשווה אותו **לשני** המשקיפים. הביקורת עוברת רק
   כשכל משקיף ראה תעבורה, אין בקשה שהוא ראה יוצאת וחסרה בדוח, אין בקשה
   שהדוח רושם וחסרה ברשת, ו-**0 בקשות אינן מקומיות**.
4. הקובץ `audit.json` נחתם ב[מפתח השחרור](/he/security/supply-chain/) ומתפרסם
   למטה.

## תוצאות לפי גרסה

לכל גרסה מאז הביקורת הראשונה יש שורה. `publish.mjs --check` נכשל כשלגרסה
שפורסמה (ב-`CHANGELOG.md`) אין קובץ ביקורת ב-`security/privacy-audits/`.

## תוויות פרטיות בחנויות

`store/privacy-labels.json` הוא המקור לתשובות *App Privacy* ב-App Store
ולטופס *Data safety* ב-Google Play:

- **לא נאסף מידע.** בהגדרות ברירת המחדל שום דבר לא יוצא מהמכשיר, וזה מה
  שביקורת המקומי-בלבד מראה.
- **נתוני קריסה, רק בתנאי אחד:** בבנייה יש מפתח לדיווח קריסות והמשתמש לא
  ביטל אותו. הנתונים לא מקושרים למשתמש ולא משמשים למעקב.
- כל תכונה אופציונלית שיכולה לשלוח משהו, ממופה לקטגוריה שלה ביומן.

בדיקה שומרת על התוויות בהתאמה לקטגוריות של היומן, למדווח הקריסות ולביקורות
שפורסמו.
