כיסוי קוד אומר אילו שורות רצו, לא אם בדיקה הייתה שמה לב לכך שהן שגויות.
בדיקות מוטציה בודקות בדיוק את זה. הן שותלות באגים קטנים בקוד, אחד בכל
פעם, ומריצות את הבדיקות בכל פעם מחדש. אם הבדיקות עדיין עוברות כשבאג נמצא
בקוד, הן פספסו אותו.

## מה נבדק

המודולים הטהורים שבאג בהם יכאיב הכי הרבה:

- **פרימיטיבים של הצפנה:** ‏ChaCha20-Poly1305,‏ BLAKE2b,‏ scrypt
  ו-Argon2id.
- הצפנת הקבצים **age**, ו**צרור המפתחות** שמחזיק את מפתחות הכספת ואת
  המכשירים.
- **מנוע הסנכרון:** מיזוג התנגשויות, המניפסט, וכותרות הבלוקים.
- **יומן הפרטיות**, שרושם וחוסם כל דבר שעלול לצאת מהמכשיר.
- **מאגר הסודות** (מפתחות API וטוקנים: מוצפנים בדפדפן, או במחזיק המפתחות
  של מערכת ההפעלה בגרסת הדסקטופ), **מנקה ה-HTML הגולמי** של התצוגה
  המקדימה, **התאמת טקסט** בעברית, **הצפנת** קבצים, מגבלות הייבוא של
  **ZIP**, ו**סביבת ההרצה של הסוכנים**.

הרשימה נמצאת ב-`scripts/mutation/targets.json`.

## הבאגים שנשתלים

| סוג | דוגמה |
|---|---|
| אופרטורים | ‏`+` ↔ `-`,‏ `<` ↔ `<=`,‏ `===` ↔ `!==`,‏ `&&` ↔ `\|\|`,‏ `<<` ↔ `>>`,‏ `^` → `&` |
| קבועים | ‏`n` → `n + 1` (`1` → `0`) |
| ערכים בוליאניים | ‏`true` ↔ `false` |
| שלילה | ‏`!x` → `x` |
| תנאים | ‏`if (c)` → `if (!(c))` |

רק קוד עובר מוטציה, אף פעם לא טיפוסים, ייבואים או הערות. מוטציה שלא
מתפרשת כקוד תקין לא נספרת. מוטציה נחשבת **נתפסה** כשבדיקה שעוברת על הקוד
האמיתי נכשלת, כשההרצה קורסת, או כשהיא נתקעת.

## הרצה

```sh
npm run test:mutation                          # כל המודולים, נכשל מתחת ל-70%
node scripts/mutation/run.mjs --module keyring # מודול אחד
node scripts/mutation/run.mjs --max 200        # מדגם גדול יותר לכל מודול
```

הדוח, עם הציון לכל מודול והשורה של כל מוטציה ששרדה, נכתב
ל-`reports/mutation/`. היעד בתוכנית הוא ציון של 70% לפחות בכל מודול.
מוטציה ששורדת במודול אבטחה צריכה לקבל בדיקה שתופסת אותה.

## רצפה של 80% בכל build של preview

המודולים הקריטיים (הרשימה `critical` ב-`targets.json`) חייבים לקבל
**80%** לפחות:

- הצפנה: הפרימיטיבים, age, ה-keyring ו-`storage/encryption`
- סנכרון: conflict, ‏manifest ו-header
- יומן הפרטיות
- המסנן של HTML גולמי
- מאגר הסודות
- כתיבה לכספת: `storage/vault/shared` ו-`handleBackend`

`npm run test:mutation` נכשל כשאחד מהם מתחת ל-80%, וכשמודול אחר כלשהו מתחת
ל-70%.

הרצה מלאה ארוכה מדי ל-build של preview, ולכן ה-build בודק **קבלה**.
`scripts/mutation/receipt.json` מתעד לכל מודול קריטי את הציון האחרון שלו ואת
ה-sha256 של הקוד שעליו הוא נמדד. `npm run mutation:check`, שער ב-build של
preview, נכשל כשמודול קריטי בענף:

- אין לו ציון בקבלה,
- הציון שלו מתחת ל-80%, או
- הוא השתנה מאז שהציון שלו נמדד.

אחרי שמשנים מודול קריטי, מודדים אותו שוב ושומרים את הקבלה בקומיט:

```sh
node scripts/mutation/run.mjs --critical --module privacyLedger --receipt
```

מודול שעוד לא נמצא בענף (הוא מגיע עם pull request אחר) מופיע ברשימה ומדולג.
