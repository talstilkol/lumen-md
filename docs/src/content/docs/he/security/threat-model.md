פרטיות היא הטענה המרכזית של Lumen, ולכן צריך להיות אפשר לבדוק אותה מבחוץ.
הדף הזה מפרט, לכל גבול שבו מידע עובר מצד אחד לאחר, את האיומים בכל קטגוריה
של STRIDE ‏(**S** התחזות, **T** שינוי, **R** הכחשה, **I** חשיפת מידע,
**D** מניעת שירות, **E** הסלמת הרשאות), מה עוצר אותם ומה נשאר פתוח. כל הגנה
מפנה לקוד או לבדיקה שמחזיקים אותה; שורה בלי הפניה היא פער ידוע.

## על מה מגינים

- **פתקים וקבצים מצורפים** — הכספת (אחסון הדפדפן, תיקייה, הטלפון).
- **סודות** — מפתחות AI, אסימוני Git וענן, סיסמאות חדרים ([סודות והצפנה](/he/security/vault/)).
- **מה שמקלידים ל-AI** — ההנחיות והפתקים שנשלחים איתן.
- **האפליקציה עצמה** — הקוד שרץ אצלכם חייב להיות הקוד ששוחרר ([שרשרת האספקה](/he/security/supply-chain/)).

## ממי מגינים

| תוקף | יכול | לא יכול (הנחה) |
|---|---|---|
| פתק או קובץ זדוני (משותף, מיובא, נקצץ, מסונכרן) | לשים כל בית בפתק, ב-`.canvas`, ב-front matter, בקישור | להריץ קוד מחוץ לארגזי החול |
| תוקף ברשת / שרת relay או signaling | לקרוא ולשנות את התעבורה שעוברת דרכו | לשבור TLS או AES-GCM |
| ספק ענן (Dropbox, ‏Drive, ‏Gist) | לקרוא, לשנות, למחוק או לעכב קבצים שהוא שומר | — |
| תוסף או בלוק חי | להריץ את הקוד שלו בארגז החול שלו | להגיע למקור של הדף, לכספת או לרשת בלי הרשאה שניתנה |
| ספק AI בענן (רק אם המשתמש בחר בו) | לראות מה שנשלח אליו | לראות משהו במדיניות `local-only` |
| מי שמחזיק את המכשיר פתוח | כל מה שהמשתמש יכול | — (מחוץ לתחום; נעילת מערכת והצפנת דיסק) |
| תלות או בנייה פרוצה | לשלוח קוד אחר | לעבור את בדיקת החתימה והבנייה החוזרת |

## פערים ידועים

- עריכות בעבודה משותפת מיוחסות מקומית, לא חתומות (R).
- סוכן שקיבל `write` כותב בלי לשאול שוב על כל קובץ (E).
- פרופיל דפדפן מועתק יכול להשתמש במפתח הסודות השמור בלי סיסמה, עד שתגיע הצפנת כספת מלאה (11.4).
- ההרשאה `<all_urls>` של הקוצץ רחבה ממה שהתנהגות "רק בלחיצה" צריכה.
- ה-fuzzer מכסה את המפענחים שקיימים בכל ענף; ‏`.base`, ‏`.excalidraw`, הערות PDF ו-manifest של תוספים מצטרפים כשהמודולים שלהם נכנסים.
