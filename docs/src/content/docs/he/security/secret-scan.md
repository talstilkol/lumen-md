‏Vite מעתיק את הערך של כל משתנה `VITE_*` שהאפליקציה קוראת אל ה-JavaScript
הציבורי. כל מי שפותח את האתר יכול לקרוא אותו. לכן טוקן, מפתח API או סיסמה
לעולם לא יהיו משתנה `VITE_*`. ‏Lumen אוכפת את זה בשלושה מקומות.

| איפה | מה נבדק | מה מכשיל |
|---|---|---|
| הבנייה (`vite build`) | כל משתנה `VITE_*` שמוגדר בסביבה או בקובץ `.env` | שם שלא נמצא ב-`security/vite-env-allowlist.json` |
| שער ה-preview ב-Vercel ‏(`npm run secrets:dist`) | כל קובץ ב-`dist/` | מחרוזת בצורת טוקן, או ערך `VITE_*` שלא ברשימה המותרת |
| הסריקה החיה (`npm run secrets:scan-live`) | ה-production, שלושת ה-previews האחרונים, ושמות ה-`VITE_*` שמוגדרים ב-Vercel | אותו דבר, ועוד שם `VITE_*` ב-Vercel שלא ברשימה המותרת |

כללי הקוד של `npm run hygiene` מונעים מ-`src/` לקרוא משתנים עם שם של סוד
(`…TOKEN`, ‏`…SECRET`, ‏`…KEY`) ולקרוא את `import.meta.env` כאובייקט שלם.
לפני #243 קריאה כזו הכניסה ל-bundle **כל** משתנה `VITE_*` של הבנייה, גם כאלה
שהאפליקציה לא השתמשה בהם. שער הרשימה המותרת מכסה גם את זה: בנייה לא יכולה
להגדיר שם שלא ברשימה.

## הרשימה המותרת

‏`security/vite-env-allowlist.json` מונה כל שם שבנייה רשאית להגדיר, עם הסיבה
שהוא ציבורי: כתובת של worker, מזהה לקוח OAuth, מזהה מחיר, מפתח ציבורי. שמות
שמתחילים ב-`VITE_VERCEL_` הם משתני המערכת של Vercel (מזהה הפריסה, הענף
והקומיט). הם לא סודות, והאפליקציה לא קוראת אף אחד מהם. ערך שמתחיל ב-`ci-canary-`
הוא קנרית לבדיקה, ומותר בכל שם.

כדי להוסיף משתנה, מוסיפים את שמו ואת הסיבה שהוא ציבורי. אם הוא סוד, אין לו
מקום כאן: שומרים אותו במאגר הסודות (`src/lib/secretStore.ts`) או בשרת.

## מה הסריקה מחפשת

- **סוד** (הסריקה נכשלת): מפתחות OpenAI ו-Anthropic ‏(`sk-`), טוקנים של GitHub
  ‏(`ghp_`, ‏`github_pat_` …), מפתחות API של Google ‏(`AIza`), מפתחות גישה של AWS,
  מפתחות live של Stripe, טוקנים של Slack, גוף של מפתח פרטי, JWT שאינו מפתח anon
  ציבורי, וערכי `VITE_*` שלא ברשימה המותרת.
- **לבדיקה** (רק ברשימה): מחרוזות hex של 32 תווים ומעלה, ו-JWT של anon. גיבובי
  תוכן ומזהי הטמעה נראים אותו דבר.

דוח לעולם לא מציג ערך שלם. הוא מציג את 4 התווים הראשונים ואת האורך.

## הרצה

```bash
npm run secrets:self-test        # plants a token of each kind in a temporary build and finds it
npm run secrets:dist             # scans dist/ after npm run build
VERCEL_TOKEN=… VERCEL_PROJECT_ID=prj_… VERCEL_TEAM_ID=team_… \
  npm run secrets:scan-live -- --report scan.md
node scripts/secrets-scan-live.mjs --url https://lumen-md.vercel.app
```

הסריקה החיה קוראת מה-API של Vercel רק את **השמות** של משתני הסביבה של
הפרויקט. היא אף פעם לא מבקשת לפענח ערך. ל-preview מוגן מגדירים
`VERCEL_AUTOMATION_BYPASS_SECRET`.

## אם סוד הוגדר כמשתנה VITE_* ‏(15.18)

1. מתייחסים אליו כציבורי. כל בנייה שרצה בזמן שהוא היה מוגדר עלולה הייתה להכניס
   אותו ל-bundle, ופריסות ישנות נשארות באוויר.
2. מבטלים אותו אצל הספק ויוצרים חדש.
3. מוחקים את משתנה ה-`VITE_*` ב-Vercel (וב-Netlify או ב-CI, אם יש).
4. שמים את הערך החדש במקום שלו: מאגר הסודות למפתח של משתמש, או secret בצד
   השרת ל-worker.
5. מריצים `npm run secrets:scan-live` ושומרים את הדוח.

אם אף סוד לא הוגדר אף פעם כ-`VITE_*`, רושמים את זה, ו-15.18 סגור.
