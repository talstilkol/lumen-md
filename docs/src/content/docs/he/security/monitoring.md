Lumen מודד כמה הוא מהיר במכשיר שלכם, ויכול לשלוח דוחות קריסה לשירות מעקב
שגיאות, אבל רק אחרי שתפעילו אותם. שניהם עובדים אותו דבר בכל בנייה.

## מדדי ביצועים: נמדדים כאן, אף פעם לא נשלחים

Lumen מודד חמישה מדדי מהירות דף בעזרת `PerformanceObserver` של הדפדפן:

| מדד | מה הוא | טוב |
|---|---|---|
| LCP | ‏Largest Contentful Paint: מתי מופיע הרכיב הגלוי הגדול ביותר | ≤ 2.5 s |
| FCP | ‏First Contentful Paint: מתי מופיע התוכן הראשון | ≤ 1.8 s |
| TTFB | ‏Time to First Byte: מתי מגיע הבית הראשון של תגובת השרת | ≤ 800 ms |
| INP | ‏Interaction to Next Paint: האינטראקציה האיטית ביותר בסשן הזה | ≤ 200 ms |
| CLS | ‏Cumulative Layout Shift: כמה הפריסה קופצת בלי פעולה שלכם | ≤ 0.1 |

הערכים נשארים בזיכרון במכשיר שלכם. פותחים אותם ב-**מדדי ריצה** בשורת
המצב, או מלוח הפקודות. הם אף פעם לא נשלחים, גם כשדוחות השגיאה פעילים. דגימה
לא שומרת כתובת דף.

## דוחות שגיאה: כבויים כברירת מחדל

Lumen שולח דוחות שגיאה רק כש**שני** התנאים מתקיימים:

1. **הפעלתם אותם.** לחצו על הכפתור **טלמטריה** בשורת המצב. בהתקנה חדשה
   הוא כבוי. לחיצה נוספת מכבה את הדוחות. הכיבוי חל מיד, גם על שגיאה שכבר
   נמצאת בדרך לדיווח.
2. **הבנייה מציינת שירות מעקב שגיאות** ב-`VITE_SENTRY_DSN`. זה יכול להיות
   Sentry או GlitchTip באירוח עצמי, שמדבר באותו פרוטוקול.

אם אחד מהם חסר, ה-SDK של Sentry אף פעם לא מורד ואף בקשה לא נשלחת. בבנייה
הרגילה אין DSN, ולכן היא לא שולחת שום בקשת ניטור. בדיקת e2e
(`e2e/monitoring.spec.ts`) בודקת זאת.

### מה יש בדוח

כל דוח נבנה מחדש מרשימת היתרים קצרה לפני שהוא יוצא מהדפדפן:

- שם המחלקה של השגיאה, כמו `TypeError`;
- שמות קובצי הסקריפט, הפונקציות ומספרי השורות של ה-stack trace;
- גרסת האפליקציה והסביבה, ושם ה-SDK והגרסה שלו.

**הודעת השגיאה אף פעם לא נשלחת.** הודעה יכולה להכיל כותרת או שורה מפתק בלי
מירכאות ("Failed to save Quarterly plan"), ושום מסנן לא יכול להבחין בזה
באמינות מהמילים של האפליקציה עצמה. ה-stack trace מראה איפה השגיאה קרתה, וזה
מספיק כדי למצוא אותה.

דוח אף פעם לא כולל:

- את הודעת השגיאה, או טקסט כלשהו שנרשם איתה;
- את כתובת הדף;
- פירורי לחם, כמו לחיצות, שורות קונסול ובקשות;
- מידע על המשתמש או כתובת IP (`infer_ip: never`);
- תגיות, מידע נוסף או הקשרים.

אין הקלטת סשן, אין מעקב ביצועים ואין מעקב סשנים.

### כל דוח מופיע ביומן הפרטיות

דוחות שגיאה עוברים דרך יומן הפרטיות (לוח הפקודות ← **יומן פרטיות…**) כמו
כל בקשה אחרת שיוצאת מהמכשיר. כל אחד מופיע בקטגוריה משלו: "Error report — only
with your consent, content removed". היומן מראה לאן הדוח הלך, מה הגודל שלו
ומה המצב שלו. במדיניות ה-AI **מקומי בלבד**, דוחות נדחים לפני שהם יוצאים, וכל
דחייה מופיעה כחסומה.

## למפעילים: הגדרת ה-DSN

הגדירו את ה-DSN בזמן הבנייה:

```bash
VITE_SENTRY_DSN=https://<public-key>@o123.ingest.sentry.io/4567 npm run build
# Docker: docker build --build-arg VITE_SENTRY_DSN=… .
```

**‏DSN אינו סוד.** ‏Sentry תכננה אותו להיות ציבורי: הוא נשלח בכל דף שמשתמש
ב-Sentry, והוא רק מאפשר ללקוח *לשלוח* אירועים לפרויקט אחד. הוא לא יכול לקרוא
מידע. לכן משתנה `VITE_*` בזמן בנייה הוא המקום הנכון בשבילו, וסורקי סודות
יכולים להתעלם ממנו.

המארח של ה-DSN מתווסף ל-`connect-src` של ה-CSP **אוטומטית בזמן הבנייה**, באותו
מנגנון כמו שאר נקודות הקצה של ההתקנה (`src/build/cspEndpoints.ts`). זה מכסה את
תגית ה-meta ב-`index.html`, את `dist/_headers` ואת תמונת ה-nginx. ב-**Vercel**,
‏`vercel.ts` מוסיף את אותו מקור לכותרת שהוא מגיש, ממשתנה הסביבה
`VITE_SENTRY_DSN` של הפרויקט. במדיניות שבמאגר אין שום מארח של שירות מעקב
שגיאות ושום wildcard.
