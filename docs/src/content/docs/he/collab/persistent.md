[חדר WebRTC](/he/collab/webrtc/) רגיל חי רק בדפדפנים שנמצאים בו: כשהאחרון
יוצא, החדר נעלם (מי ששמר את הפתק נשאר עם העותק שלו). **שרת מתמשך** שומר את
המסמך של כל חדר, כך שכל אחד יכול להצטרף אחר כך ולמצוא את הגרסה האחרונה, גם
כשאף אחד אחר לא מחובר.

## הרצת השרת

`sync-server/persistent-server.js` הוא שרת
[y-websocket](https://github.com/yjs/y-websocket) קטן ששומר כל חדר בדיסק עם
LevelDB.

```bash
cd sync-server
npm install @y/websocket-server y-leveldb
PORT=4444 node persistent-server.js        # ws://localhost:4444
```

- **אחסון:** `YJS_STORAGE_DIR` (ברירת מחדל `./.yjs-persistence`). ב-Fly.io,
  ‏Render או Railway מכוונים אותו לכרך מחובר. חבילת ה-Docker compose משתמשת
  ב-`/data/yjs`.
- **טוקן גישה:** מפעילים עם `COLLAB_TOKEN=<מחרוזת אקראית ארוכה>` והשרת מקבל
  רק לקוחות ששולחים את אותו טוקן. בלעדיו, כל מי שיודע שם של חדר יכול לקרוא את
  העדכונים (המוצפנים) של החדר ולהוסיף משלו.
- **בריאות:** `GET /healthz` עונה `200 {"ok":true}`.
- שימו אותו מאחורי TLS ‏(`wss://`) לפני שחושפים אותו.

ב-`DEPLOY.md` יש את השלבים ל-Fly.io.

## לכוון את Lumen אליו

מגדירים בזמן בניית Lumen:

```bash
VITE_YJS_WEBSOCKET_URL=wss://collab.example.com
VITE_YJS_WEBSOCKET_TOKEN=<אותו COLLAB_TOKEN>   # אם לשרת יש כזה
```

אז Lumen מתחברת לשרת לצד רשת העמיתים. כשחיוב מוגדר, חדרים מתמשכים דורשים
מסלול Pro או Team; בבנייה באירוח עצמי בלי חיוב הם פעילים.

## מה השרת יכול לקרוא

בחדר עם סיסמה — כלום. השרת שומר רק מעטפות מוצפנות ב-AES-GCM-256, לעולם לא את
הטקסט. לחדרים שנוצרים היום יש שמות אקראיים של 128 ביט והם מוצפנים מקצה לקצה,
כך שהטוקן הוא שער שני, לא היחיד. מה שהשרת כן רואה: שמות חדרים, וגודל ותזמון
של עדכונים. ראו [הצפנה מקצה לקצה](/he/collab/encryption/).
