שיתוף חי עובד גם בלי שרת: הדפדפנים מתחברים זה לזה ישירות ב-[WebRTC](/he/collab/webrtc/).
שרת מוסיף שני דברים: אנשים ברשתות שונות מוצאים זה את זה (איתות), וחדר נשאר זמין גם
כשאף אחד אחר לא מחובר ([חדרים מתמשכים](/he/collab/persistent/)).

השרת הציבורי של Lumen עושה את שניהם, בחינם, ו**אף פעם לא רואה מה שאתם כותבים**.

## מה השרת רואה ומה לא

| | השרת |
|---|---|
| הטקסט של הפתק | **אף פעם.** הוא מקבל רק חדרים עם סיסמה ([הצפנה מקצה לקצה](/he/collab/encryption/)). כל שינוי נבדק לפני שהוא נקלט. שינוי שאינו מעטפה מוצפנת סוגר את החיבור, ושום דבר ממנו לא נשמר. |
| המסמך המוצפן של החדר | נשמר, כדי שהחדר יישאר גם כשכולם יצאו. זה טקסט מוצפן. בלי סיסמת החדר אף אחד לא יכול לקרוא אותו, גם לא השרת. |
| מי יכול להצטרף לחדר | רק מי שיש לו את סיסמת החדר. האפליקציה מוכיחה שהסיסמה אצלה בעזרת ערך שנגזר ממנה, ואינו מפתח ההצפנה. השרת שומר רק גיבוב של הערך הזה. שם החדר בשרת נושא התחייבות לגיבוב הזה, ולכן החדר מקבל רק את הערך שמתאים לה, גם מהאדם הראשון שמתחבר. לדעת את שם החדר לא מספיק כדי להצטרף אליו, לכתוב אליו, לשמור אותו או לנעול את בעליו בחוץ. חדר חדש גם עולה לאפליקציה כמה שניות של עבודה. |
| כמה חדרים חדשים | מוגבל ליום: 2,000 בכל השרת, 20 לכל כתובת (כתובת IPv4, או ‎/64 של IPv6) ו-80 לכל ‎/48 של IPv6. גם מה שנשמר מוגבל: 20,000 חדרים, ‏4GB בסך הכול ו-50 חדרים לכל כתובת. כשהשרת מלא, חדר חדש תופס את מקומו של החדר השמור הקטן ביותר שאף אחד לא הצטרף אליו שוב ב-14 הימים האחרונים, ואף פעם לא של חדר שמישהו מחובר אליו. הכתובות נספרות לפי גיבוב עם מפתח שמתחלף כל יום, ואף פעם לא נשמרות כמו שהן; חדר שמור שומר רק גיבוב של 20 ביט של הכתובת שיצרה אותו, שמשותף לכ-4,000 כתובות IPv4. אחרי שעוברים מגבלה, חדר חדש עובד רק ישירות בין המכשירים, וחדרים שכבר קיימים לא מושפעים. |
| חדרים שאף אחד לא משתמש בהם | נמחקים **90 יום** אחרי השינוי האחרון. נחשב רק שינוי, ורק מי שיש לו את סיסמת החדר יכול לעשות שינוי: התחברות, או קריאה בלבד, לא שומרת כלום. |
| כתובת ה-IP שלכם | לא נשמרת באף יומן. קוד השרת לא רושם דבר על חיבורים, ורישום הבקשות כבוי. Cloudflare, שמארחת את השרת, רואה כתובות כמו כל ספק רשת. |
| סמנים ושמות תצוגה | עוברים בין האנשים בחדר בזמן שהם מחוברים. לא נשמרים. השם אקראי ("Saffron", ‏"Willow"), לא השם שלכם. |
| שמות חדרים, שעות וגדלים | השרת רואה אותם. שמות החדרים אקראיים. |

## אם השרת לא זמין

האפליקציה ממשיכה לעבוד. חדרים מתחברים ישירות ב-WebRTC, והפתקים נמצאים במכשיר שלכם.
מצב השרת זמין ב-`/healthz` לכלי ניטור זמינות.

## איפה הוא רץ ולמה

ב-**Cloudflare Workers עם Durable Objects**, בתוכנית החינמית: אובייקט קטן לכל חדר,
שנוצר קרוב לאדם הראשון שפותח אותו (ל-Cloudflare יש מרכז נתונים בתל אביב). השווינו
שלוש אפשרויות חינמיות:

- **Cloudflare Workers + Durable Objects** (נבחר): התוכנית החינמית כוללת WebSockets
  עם שינה (hibernation), אחסון SQLite ‏(5GB) ו-100,000 בקשות ביום. 100 הודעות WebSocket
  נספרות כ-5 בקשות.
- **Fly.io**: אין יותר הקצאה חינמית לחשבונות חדשים.
- **Deno Deploy**: ‏WebSockets עובדים, אבל אין מקום אחד שמחזיק חדר, כך שמשתתפים על
  מופעים שונים לא היו רואים זה את זה.

## הפעלה

השרת נמצא ב-`edge-workers/collab/` (הוא משתמש באותו קוד חדר כמו שרת ה-Node
שב-`sync-server/`). מי שמחזיק את חשבון Cloudflare מפעיל אותו בפקודה אחת:

```sh
npm run collab:deploy
```

הפקודה פורסת את ה-Worker, קובעת את סוד האסימונים, בודקת את `/healthz` ומדפיסה את שני
משתני הבנייה של האפליקציה: `VITE_YJS_WEBSOCKET_URL` ו-`VITE_WEBRTC_SIGNALING_URL`.
איך פורסים אותו יחד עם ממסר הסנכרון המוצפן ומודדים את ההשהיה מהמקום שלכם: ב[שרתי השיתוף
ב-Cloudflare](/he/sync/relay-server/) ‏(`npm run owner:share`).

כדי להריץ שרת Node משלכם עם אותם כללים, מפעילים את `sync-server/collab-server.mjs`
עם `COLLAB_E2EE_ONLY=1`. חדרים שלא השתנו `COLLAB_RETENTION_DAYS` ימים (90 כברירת
מחדל) נמחקים.
