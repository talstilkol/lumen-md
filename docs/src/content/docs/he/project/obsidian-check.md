הבדיקות של Lumen קוראות כספות אמיתיות: עשר כספות ציבוריות, נעוצות ל-commit,
עם רישיונות שנבדקו. שלוש מהן נכתבו ב-Obsidian 1.14–1.15. אבל הבדיקות לא
יכולות להריץ את Obsidian עצמו. רשימת הבדיקה הזו כן מריצה אותו, ב-Mac שמותקן
בו Obsidian. זה לוקח כ-20 דקות.

## מה Obsidian 1.14–1.15 שינה בקבצים

מתוך יומן השינויים של Obsidian (‏1.14.4 עד 1.15.1), ומה Lumen עושה עם כל שינוי:

| שינוי | ‏Lumen |
|---|---|
| ‏`groupOrder:` בתצוגה מקובצת: הקבוצות שמוצגות, לפי הסדר; פריט ריק הוא "בלי ערך" | מוצגות בסדר הזה, וקבוצות שלא ברשימה מוסתרות, כמו שכתוב בתיעוד של Bases. ‏`groupOrder` שאינו רשימה לא נלקח בחשבון (התיקון של 1.14.4). |
| סינון שמשנים את סדרו בגרירה ומעבירים בין *All views* ל-*This view* | ‏`moveFilter()` כותב את שניהם. שאר הקובץ, כולל הערות, לא משתנה. שינוי סדר והחזרה נותנים את אותם בתים. |
| ערך בסינון עם `"` או `\` נשמר עם escape (התיקון של 1.15.0) | נקרא כפי שנכתב. ‏Lumen כותב ערך כזה באותה דרך (`basesTextLiteral()`). |
| מפתחות תצוגה שהאפליקציה כותבת: `columnSize`, ‏`columnWidth`, ‏`imageFit`, ‏`imageAspectRatio`, ‏`enableSearch`, ‏`rowHeight` | נשמרים כפי שנכתבו. |
| נוסחאות ארוכות שנוצרות אוטומטית (התוסף TaskNotes כותב אחת של 2,384 תווים) | ביטוי Bases יכול להגיע ל-8,000 תווים. תקציב החישוב לא השתנה. |
| ‏Canvas, ‏callouts | אין שינוי בפורמט הקובץ ב-1.15 (רק תיקוני ביצועים ותצוגה). |

## רשימת הבדיקה

1. **מכינים כספת ש-Lumen שמר.** מעתיקים אחת מכספות הקורפוס
   (`src/__tests__/fixtures/obsidian-corpus/<vault>`) לתיקייה חדשה, ופותחים
   את התיקייה ב-Lumen. ואז, ב-Lumen:
   - ממיינים תצוגה אחת בלחיצה על כותרת עמודה;
   - עורכים מאפיין אחד בפתק;
   - שומרים קנבס אחד;
   - שומרים וסוגרים את Lumen.
2. **כותבים את הבדיקות:**
   `npm run obsidian:compare -- prepare <folder>`
   זה כותב קובץ `.base` לבדיקה לכל תצוגה, ליד כל base, ומתקין את התוסף
   הקטן *Lumen compare* ב-`<folder>/.obsidian/plugins/`.
3. **פותחים את התיקייה ב-Obsidian** (‏1.15.1 ומעלה): *Open folder as vault*.
   ‏Settings ← Community plugins ← מדליקים את *Lumen compare*.
4. **מחפשים אזהרות בזמן הפתיחה.** רושמים כל הודעה על קובץ `.base` או
   `.canvas` או על מאפיינים. לא אמורה להיות אף אחת.
5. **מריצים את הבדיקות:** לוח הפקודות ← *Lumen compare: Run every probe*.
   ‏Obsidian פותח כל קובץ בדיקה בתורו, ואחר כך כל `.base` ו-`.canvas` מקורי,
   ושומר את מה שהציג ב-`_lumen-compare/results/`. מחכים להודעה שמסתיימת
   ב-"files opened cleanly".
6. **משווים:**
   `npm run obsidian:compare -- diff <folder> --out obsidian-diff.md`
   הדוח מציג כל תצוגה כ-✅ (אותן שורות), ‏↕ (אותן שורות בסדר אחר, בתצוגה
   שממיינת או מקבצת), ‏❌ (שורות שונות, עם הנתיבים) או ⏳ (אין תוצאה
   מ-Obsidian). הוא מציג גם את הקבצים ש-Obsidian פתח בלי בעיה. היציאה היא 1
   אם יש תצוגה כלשהי ב-❌ או ב-⏳.
7. **מנקים:** `npm run obsidian:compare -- clean <folder>`
8. **מדווחים:** מצרפים את `obsidian-diff.md` למשימה בתוכנית (W6.34), ופותחים
   issue לכל ❌ עם שתי רשימות הנתיבים שלו.

## למה ההשוואה הוגנת

- כל קובץ בדיקה יושב ליד ה-base שלו, כך ש-`this.file`, התיקייה שלו והקישורים
  נפתרים אותו דבר בשתי האפליקציות.
- הצד של Lumen רץ על אותם קבצים בדיסק, כולל קובצי הבדיקה, עם הגדלים והזמנים
  האמיתיים שלהם.
- הסדר מושווה רק בתצוגה שממיינת או מקבצת. במקומות אחרים אף אפליקציה לא
  מבטיחה סדר.
- התוסף משתמש ב-API הציבורי של תצוגות Bases (`registerBasesView`). הוא לא
  שולח שום בקשה, וכותב רק בתוך `_lumen-compare/`.
